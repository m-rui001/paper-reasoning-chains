# 语料质量门槛（整改执行标准）

适用：m-rui001 的 LLM 训练语料仓库。目标是把“抓下来/生成出来”的原始产物提升为可复核、可复现、可训练的数据集。

## 硬性门槛

1. 编码：UTF-8（无 BOM），换行 LF；不得含 U+FFFD 替换字符（不可修复时删除该行/该文件）。
2. 完整性：不得为截断、占位、空文件；技术总结最短 400 字符，且必须有标题与来源行。
3. 来源：每个文档必须能回溯到 DOI/arXiv ID/URL；缺失则补，补不到则隔离。
4. 去重：完全相同内容只保留一份；保留路径按“语言目录正确 > 路径更短 > 字典序”选择。
5. 噪声：删除 OCR 页眉页脚、提取标记、字体版权声明、菜单/UI/引擎配置、重复行；不得删除正文以“看起来像噪声”。
6. 结构：Markdown 必须有唯一一级标题；不得出现模板化栏目堆砌；公式/符号不得被“修复”成臆造内容。
7. 语言：目录语言与正文语言一致；中文目录中的成句日文/英文必须翻译或移入正确目录；中日对照文件保留双语并明确标注。
8. 许可：代码/脚本可用 MIT/Apache；第三方正文的版权不因仓库 LICENSE 改变，README 必须写清。

## 删除门槛（只有满足其一才删）

- 空文件、< 20 字符、纯符号/乱码。
- 替换字符比例 > 2%，或不可读字符占主导。
- 重复行占非空行 > 50%（且非有意复沓）。
- 菜单/UI/引擎配置/制作名单等非正文，且无叙事价值。
- 与另一文件字节级完全相同（保留一份）。
- 摘要类文档 < 400 字符，或只有标题/来源、无正文。

其余“质量偏低但可读”的样本不删：在 manifest 中标记 `quality` 与 `defect`，必要时修复。删除必须写入 `REJECTED.csv`（原路径、原因、sha1、字符数），git 历史即备份。

## 机翻/翻译腔

- 只对可证实缺陷动手：未翻译的成句日文、语言错置、明显重复、乱码、术语前后不一致。
- 不做整篇自由改写；改写必须保持情节、人名、术语、行序与格式，并在 manifest 标记 `repaired`。
- 修复后必须通过：行数差异 ≤ 2%、无新增乱码、无内容删减（抽样比对）。

## 交付

每个仓库交付：清洗/校验脚本 + `MANIFEST.csv`（或等价索引）+ `QUALITY.md`（前后计数、缺陷分布、未解决项）+ README 更新。脚本必须可重跑，报告数字必须由脚本产生。

# 当检测器换一个阈值，跟踪排名就变了：UA-DETRAC 如何把检测质量纳入多目标跟踪评测

**UA-DETRAC: A new benchmark and protocol for multi-object detection and tracking**（2020，DOI: 10.1016/j.cviu.2020.102907）

## 一个被现有评测协议掩盖的问题

多目标跟踪（MOT）系统在工程上通常被拆成两步：先用检测器在每帧里找出目标（一般给出边界框），再用跟踪器把这些框跨帧连成轨迹。论文在开篇就给出了一个明确的定义——MOT 系统 = 检测 + 跟踪 [page 1]。既然检测是系统的输入端，检测质量理应深刻影响最终跟踪表现。但作者指出，当时主流的 MOT 评测协议恰恰把检测这一步"固定"了：用某一套预先设定好的检测结果作为所有跟踪器的共同输入，然后只比较跟踪器 [page 1]。

这种做法的初衷是让评测独立于检测器的波动，看起来更"公平"。但作者用一个直接的实验观察质疑了它：在 UA-DETRAC、MOT16 和 KITTI-T 三个数据集上，用四种检测器（DPM、ACF、R-CNN、CompACT）和七种跟踪器（GOG、CEM、DCT、IHTLS、H2T、CMOT、TBD）组合成完整的 MOT 系统，然后改变检测分数阈值，画出精度–召回（PR）曲线，并在每个 (precision, recall) 点上记录系统的 MOTA 分数（Fig. 1）[page 2]。结果很清楚：**不同跟踪器之间的相对排名会随检测设置而改变**。论文举了一个具体例子：在精度–召回为 (0.433, 0.341) 时，CEM 跟踪器的 MOTA 高于 DCT；但在 (0.674, 0.183) 时，CEM 反而低于 DCT [page 3]。MOT16 和 KITTI-T 上也有类似现象。

这就构成了论文的核心动机：如果换一个检测阈值就能翻转跟踪器的排名，那么"用单一检测设置来比较跟踪器"得到的结论就是不稳健、甚至可能误导的。作者由此提出，评测必须把检测器的**整个**精度–召回行为纳入进来，而不是只取一个点。

## 数据集：为"检测+跟踪联合评测"而建

支撑这套论证的基础是一个新数据集。UA-DETRAC 包含 100 段真实交通场景视频，超过 140,000 帧，由 Canon EOS 550D 在 24 个不同地点拍摄，涵盖城市高速、十字路口、T 型路口等，25 fps，分辨率 960×540 [page 3]。标注规模是：8,250 辆车、共 121 万个车辆边界框，由 10 余名领域专家标注两个多月，并经过多轮交叉校验 [page 3]。数据集分为训练集（60 段）和测试集（40 段），且刻意让训练与测试视频取自不同地点但交通条件相似，以降低过拟合特定场景的风险 [page 3–4]。

标注不只是框，还带有可用于分层分析的属性：车辆类型（car、bus、van、others）、光照（cloudy、night、sunny、rainy）、尺度（按边界框面积平方根分为 0–50、50–150、>150 像素三档）、遮挡比例（无遮挡、1%–50% 部分遮挡、>50% 重度遮挡）、截断比例 [page 4–5]。这些属性后面直接支撑了"检测器在什么条件下失效"的分析。

测试集还按难度分层。检测难度用 EdgeBox 在每帧 5000 个候选框下的召回率来划分：easy（10 段）、medium（20 段）、hard（10 段），平均召回率分别为 97.0%、85.0%、64.0%（Fig. 4）[page 4]。跟踪难度则用六种跟踪器与四种检测器组合出的平均 PR-MOTA 分数来划分（Fig. 5）[page 4–5]。Table 1 把 UA-DETRAC 与 INRIA、ETH、Caltech、KITTI、MOT15/16 等既有数据集在帧数、轨迹数、框数、任务类型、目标类型、是否含光照/遮挡标注等方面做了对比，突出其在车辆检测与跟踪联合评测上的体量和标注丰富度 [page 2]。

## 新协议的关键一步：把 MOTA 沿 PR 曲线积分

论文提出的评测协议分两层。检测层比较常规：对每个检测器生成完整 PR 曲线，命中判定沿用 KITTI-D 的 0.7 交并比阈值，用 PASCAL VOC 的 11 点召回平均计算 AP 来排名 [page 7]。

真正的新意在于跟踪层。作者定义了 PR-MOTA 曲线：它是一个三维曲线，刻画检测的 (precision, recall) 与跟踪的 MOTA 之间的关系（Fig. 6）[page 7–8]。生成步骤是：

1. 逐步改变检测阈值，得到一系列对应不同 (p, r) 的检测结果，这些点构成检测器的 PR 曲线；
2. 对每个 (p, r) 对应的检测结果跑一遍跟踪算法，算出 MOTA 值 Ψ(p, r)；
3. 把这些 MOTA 值沿 PR 曲线积分，得到 PR-MOTA 分数 Ω* = ½ ∫ Ψ(p, r) ds，几何上就是 PR-MOTA 曲线沿 PR 曲线扫出的曲面（带符号）面积 [page 8]。

这里有一个值得注意的推理细节。作者明确说，**不能**用 PR-MOTA 曲线上的最大值来比较跟踪器，因为那只是某一个检测设置下的表现；他们想要的是一个跟踪器"在检测器各种设置下都能表现好"的度量，所以取沿整条 PR 曲线的平均 MOTA [page 8 脚注 9]。这个选择直接回应了 Fig. 1 揭示的排名翻转问题：如果只看单点，排名不稳；沿曲线积分，则把检测器全谱系的表现都纳入进来。其他指标（PR-MOTP、PR-MT、PR-ML、PR-IDS、PR-FM、PR-FP、PR-FN）用同样方式计算 [page 8]。排名规则是：先比 PR-MOTA，相同再比 PR-MOTP [page 9]。

附录给出了 Ω* 取值范围的证明：由于 MOTA ∈ (−∞, 100]，Ω* 下界为 −∞；通过把积分写成黎曼和并利用 |Δp|、|Δr| 各自求和不超过 1，得到上界 100%，即 Ω* ∈ (−∞, 100%]（公式 2–3）[page 17–19]。作者还指出，取到上界需要两个理想条件同时成立——PR 曲线退化为坐标轴、且跟踪器在任何检测下都能达到 MOTA=100——这在现实中通常不成立 [page 19]。这个证明本身不改变结论，但为"分数可跨系统比较"提供了量纲上的保证。

作者也交代了与既有替代方案的差别。Solera 等人曾提出用多组扰动后的真值标注作为检测输入来评测，但作者认为这种合成扰动不能反映真实检测器的行为，而且逐帧独立扰动与真实检测器的工作方式不符；UA-DETRAC 协议则基于最先进检测器的**实际输出**、覆盖完整精度–召回范围 [page 3, page 9]。

## 检测器在哪些条件下失效

在报告跟踪结果之前，论文先用 AP 刻画了检测器本身的表现，这部分为后面的跟踪分析提供了"检测质量"的坐标。

整体上，DPM 和 ACF 在车辆检测上表现不佳，AP 仅 25.74% 和 46.44%；R-CNN 略好，49.23%；CompACT 53.31%；较新的检测器超过 60%，Faster R-CNN 62.13%、YOLOv3 76.17%、RD2 85.35%（Fig. 7a）[page 9]。从 easy 到 hard 子集，各检测器 AP 下降 15–20%，最好的 RD2 在 hard 子集也只有 76.64% [page 9]。

分层属性揭示了更具体的失效模式：

- **光照**：rainy 和 night 场景下所有方法 AP 都低于 80%，只有 RD2 在夜间达到 86.59%；cloudy 和 sunny 下 RD2 分别达 89.67% 和 90.49%（Fig. 8）[page 10]。
- **车辆类型**：检测器基本只在 car 上表现好（RD2 达 84.49%）；在 others 类别上，Faster R-CNN 的 AP 只有 17.07%，反而优于包括 RD2 在内的其他检测器。作者给出两点解释：一是不同车辆的尺度和长宽比变化大，二是 others 类训练样本极少，仅占训练集的 0.52%（Fig. 3a、Fig. 9）[page 10]。作者推测 Faster R-CNN 的优势可能来自 RPN 能有效减少候选位置、过滤背景、缓解类别不平衡——这里用的是"can be that"，属于可能解释而非确证 [page 10]。
- **尺度**：小尺度车辆上多数检测器 AP 超过 30%，RD2 最好（66.72%）；CSP 因采用无锚框框架、用点表示目标，只有 40.08%。中尺度上 RD2 达 86.63%，大尺度上 YOLOv3 最好（76.53%）（Fig. 10）[page 10]。
- **遮挡**：部分遮挡（1%–50%）时检测器 AP 下降超过 15%；重度遮挡（>50%）时所有检测器 AP 都低于 20%（Fig. 11）[page 10]。

这些数字本身是检测结果，但它们为下一节的跟踪分析提供了关键背景：跟踪系统的输入质量在不同场景下差异巨大，因此"固定一个检测设置"的评测很可能只反映了某个特定质量水平下的表现。

## 检测质量如何传导到跟踪，以及为什么排名会翻转

跟踪实验用 6 种检测器（DPM、ACF、R-CNN、CompACT、Faster R-CNN、EB）和 10 种跟踪器（GOG、CEM、DCT、IHTLS、H2T、CMOT、TBD、MHT、IOU、KIOU）组合，在 UA-DETRAC 测试集上评测 [page 7]。Table 3 给出整体结果，Table 4–6 给出 easy/medium/hard 子集，Table 7–10 给出 cloudy/rainy/sunny/night 子集。

整体上，现有 MOT 系统表现并不好：最高 PR-MOTA 只有 21.1%（EB+KIOU），DPM+CMOT 最差，为 −3.4% [page 11]。Table 2 直接对比了 PR-MOTA 与"所有检测阈值中最好的 MOTA"：例如 EB+KIOU 的 PR-MOTA 是 21.1，而最佳单点 MOTA 是 62.1；Faster R-CNN+MHT 是 14.5 对 58.2 [page 10]。这个对比本身就说明，单点 MOTA 会显著高估系统在检测质量波动下的稳健性。

一个总体趋势是：更好的检测器通常带来更好的 MOT 系统。用 DPM、ACF、R-CNN、CompACT、Faster R-CNN 时，所有跟踪器的平均 PR-MOTA 分别为 0.41%、7.84%、9.49%、11.40%、11.98%（Fig. 12）[page 11]。但作者紧接着指出**反例**：CompACT+GOG（14.2%）优于 Faster R-CNN+GOG（13.7%），尽管 Faster R-CNN 检测更好；ACF+CEM（4.5%）优于 R-CNN+CEM（2.7%）；R-CNN+DCT（11.7%）优于 CompACT+DCT（10.8%）[page 14]。Fig. 12 中不同检测器的性能曲线相互交织，且不同跟踪器各自的最佳搭档不同——GOG 在整体集上配 CompACT 最好，DCT 则配 R-CNN 最好 [page 14]。

这些反例是论文论证的关键转折。它们说明"检测越好、跟踪越好"只是趋势而非定律，检测器与跟踪器之间存在匹配关系。作者据此得出一个方法论结论：**为每个跟踪算法选择合适的检测器很重要，而且为了全面公平地评测跟踪方法，需要开发不同类型的检测器，而不是只用某一个特定检测器** [page 14]。这正是新协议要解决的问题——如果评测只固定一个检测器，就可能恰好落在某个跟踪器的"不利搭档"上，得出误导性排名。

论文还从跟踪器机制角度解释了为什么不同组合表现不同。H2T、DCT、IHTLS 采用局部到全局的优化策略来关联检测，但不善于处理误检；当输入检测有效时，它们的外观/运动模型和轨迹精化机制能帮助准确跟踪。TBD 用生成模型学习交通模式的高层语义，配上有效检测器时能生成准确轨迹，在 Faster R-CNN 下达到 14.4% PR-MOTA。CEM 用全局能量最小化来抑制误检，因此在输入检测较差（如 DPM）时反而比其他跟踪器好，但它不利用目标外观信息，所以检测变好时增益不明显 [page 12–14]。这些解释把"组合效应"落到了具体机制上，而不只是统计观察。

在子集层面，hard 子集上没有任何方法表现好，最好的 EB+KIOU 也只有 13.1% PR-MOTA，且有 12 个系统（如 R-CNN+GOG、ACF+CMOT、DPM+TBD）PR-MOTA 低于 0% [page 15]。这既说明数据集难度，也说明现有方法在困难场景下的脆弱性。在 cloudy 和 rainy 子集上，CompACT+GOG 反而优于用 EB 检测器的组合，作者由此指出"不同场景需要用不同检测器" [page 15]。

其他指标也揭示了权衡。GOG 虽然 PR-MOTA 不错，但 PR-IDS 和 PR-FM 明显偏高：Faster R-CNN+GOG 的 PR-IDS 为 2213.4，而 Faster R-CNN+H2T 只有 686.6；CompACT+GOG 为 3334.6，CompACT+CMOT 仅 285.3；最高的 PR-IDS（7834.5）和 PR-FM（7401.0）都来自 R-CNN+GOG [page 15]。作者解释 GOG 用贪心算法在流网络上求解，可能产生更多虚假轨迹 [page 15]。因此论文给出面向不同应用的选型建议：监控场景重视轨迹准确性（低 PR-IDS、PR-FM），EB+KIOU 更合适；交通安全监测更在意漏检（PR-FN），Faster R-CNN+MHT 或 EB+KIOU 更可靠 [page 15]。

## 结论成立的条件与作者承认的边界

论文的结论——"评测 MOT 必须考虑检测质量的全谱系，单点检测设置不足"——建立在几个前提上，作者也明确交代了适用范围。

首先是**协议本身的适用边界**。作者在结论中承认，提出的协议只能用于以检测框为输入的跟踪方法；对于在似然图上操作的跟踪方法，需要先用阈值确定每帧的边界框，才能套用该协议 [page 16]。此外，为降低评测计算量，作者认为有必要设计一种不需要调节输入检测精度/召回率的新协议 [page 16]——这等于承认当前协议在计算上是有代价的。

其次是**指标设计的场景依赖性**。作者指出当前指标是为通用跟踪设计的，但监控场景需要可靠轨迹（应更强调 IDS），自动驾驶则应不惜代价避免漏检（可容忍 IDS），因此设计能适配不同应用需求的综合指标是有意义的方向 [page 16]。这意味着 PR-MOTA/PR-MOTP 并非普适最优，而是当前阶段的一个折中。

第三是**运行时间比较的局限**。作者明确说，由于检测算法在不同平台上开发（R-CNN、Faster R-CNN 训练和测试都需要 GPU），公平比较运行效率很困难 [page 15]。Table 11 和 Table 12 给出了各检测器和跟踪器的帧率，但作者没有据此下强结论，只是说在计算资源不受限时深度学习方法在精度上更有吸引力，在资源受限时 ACF+CMOT、ACF+H2T 在效率和精度间较平衡 [page 16]。

还有一点需要读者自己留意：论文中"检测质量影响跟踪"的论证主要是**相关性**层面的——它展示了不同检测设置下跟踪表现和排名的变化，并从机制上给出解释，但没有做严格的因果识别。作者用词也较谨慎（"suggest"、"can be"、"may"），读者不宜把"更好的检测器导致更好的跟踪"读成确定性因果律，因为反例（CompACT+GOG 优于 Faster R-CNN+GOG 等）恰恰说明这种关系是条件性的。

## 这篇论文真正改变了什么

把论证串起来看，论文的逻辑链是：现有协议固定单一检测设置 → 实验显示换检测阈值会翻转跟踪器排名（Fig. 1）→ 因此单点评测不充分 → 提出沿 PR 曲线积分的 PR-MOTA 等指标（Fig. 6，公式 2–3）→ 用新指标在大规模新数据集上评测 → 发现检测与跟踪存在匹配效应、不同场景需要不同组合、困难子集上现有方法普遍失效 → 据此给出选型建议和未来方向。

其中最关键的一步，是把"跟踪器比较"从"在某个检测点上的比较"重新定义为"在检测器整个精度–召回行为上的平均表现"。这一步之所以必要，正是因为 Fig. 1 和 Table 2 所展示的：单点 MOTA 与沿曲线积分的 PR-MOTA 差距巨大（如 62.1 对 21.1），且单点排名不稳定。论文没有声称新指标解决了所有问题——它承认计算代价、适用对象限制和场景依赖——但它确实把"检测质量"从一个被固定的背景变量，变成了评测中显式建模的维度。对于任何要报告 MOT 系统性能的研究者，这提供了一个更诚实的比较框架：不是问"你的跟踪器在某个检测器下多好"，而是问"它在检测器各种工作点下整体多稳"。

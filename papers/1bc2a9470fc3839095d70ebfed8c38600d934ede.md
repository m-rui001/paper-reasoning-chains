# TON_IoT：用编排式边缘—雾—云测试床生成异构安全数据集

原文题名：*TON_IoT Datasets: A Distributed Architecture for Evaluating Artificial Intelligence-based Security Systems in IoT Networks*（期刊预印本标注为 *A new distributed architecture for evaluating AI-based security systems at the edge: Network TON IoT datasets*），2021 年，DOI: 10.1016/j.scs.2021.102994。

## 论文要解决的不是"再做一个数据集"，而是"缺一个能同时产生多源数据的测试床"

作者的核心主张有两层。第一层是架构层面的：现有 IoT 安全数据集大多来自静态、单一来源的测试环境，无法反映真实 IoT 网络中边缘、雾、云三层交互的复杂性，因此需要一个可编排的动态测试床 [page 4]。第二层是数据层面的：基于该测试床生成的 TON_IoT 数据集，包含网络流量、Windows/Linux 审计轨迹、IoT 遥测四类异构数据源，并配有可验证的攻击事件真值标签，因而比现有数据集更适合评估多种 AI 安全应用 [page 5][page 31]。

这两层主张是递进关系：架构是手段，数据集是产物，而"异构 + 真值标签 + 多攻击场景"是作者用来区分自己与既有工作的三个关键卖点。

## 从架构到数据：关键推理链

作者的论证起点是对现有数据集的系统性批评。论文逐一列举了 KDD99/NSL-KDD、CAIDA、DEFCON、UNIBS、LBNL、Kyoto、DARPA 2009、CDX、CTU-13、TUIDS、ISCX、CICIDS2017、N-BaIoT、UNSW-NB15、Bot-IoT 等数据集，归纳出三类共同缺陷：缺乏可信的攻击真值、缺乏异构数据源、只能服务于特定安全任务 [page 5–8]。这个批评为后续的"我们做了什么不同"提供了对照基线。

架构部分（第 3 节）是论证的枢纽。作者使用 NSX vCloud NFV 平台，在 UNSW Canberra 的 IoT 实验室部署了一个包含边缘、雾、云三层的测试床 [page 8–9]。边缘层是物理设备和主机；雾层通过 VMware NSX 和 vSphere 实现 SDN、NFV 和服务编排，运行 17 个虚拟机；云层连接公共 MQTT 仪表板、脆弱 PHP 网站和云分析服务 [page 10–11]。这个架构的关键设计意图是：让攻击和正常行为能够在三层之间真实地传播，从而同时触发网络、主机和 IoT 服务三个层面的日志记录。

数据收集的设计直接服务于"异构"目标。作者部署了五类雾节点系统：编排服务器（Ubuntu 14.04，运行 DNS、HTTP、DHCP、邮件、Kerberos、FTP 和 Ostinato 流量生成器）、中间件服务器（Ubuntu 18.04，运行 Node-RED 和 Mosquitto MQTT broker，模拟七种 IoT 传感器）、客户端系统（Windows 7/10、DVWA、OWASP Shepherd、Metasploitable3）、攻击系统（Kali Linux，10 个静态 IP）、数据管理系统（Security Onion、netsniff-ng、Zeek）[page 12–15]。四类日志工具分别捕获 Windows 审计数据、Linux atop 数据、MQTT 遥测数据和网络 pcap 流量 [page 15]。

这里有一个值得注意的推理步骤：作者声称四类数据源是"并发收集"的，并且用相同的攻击时间戳和 IP 地址进行标注 [page 16]。这意味着标签的可靠性依赖于攻击脚本执行时间与日志时间戳的精确对齐。论文没有详细说明时间同步机制或对齐误差范围，这是读者需要留意的隐含假设。

## 九类攻击与 44 个特征：数据集的构成

第 4 节描述了九类攻击场景：扫描、DoS、DDoS、勒索软件、后门、注入、XSS、密码破解、MITM [page 17–19]。每类攻击都给出了具体的工具和命令示例，例如使用 Scapy 发送 DoS 包、使用 ufonet 发起 DDoS、使用 Metasploit 的 eternalblue 漏洞执行勒索软件、使用 hydra 和 cewl 进行密码破解、使用 Ettercap 执行 ARP 欺骗 [page 17–19]。这些细节增强了数据集的可复现性主张。

第 5 节说明 Zeek 工具从 pcap 文件中提取了 44 个流特征，分为四组：连接特征（12 个，如 src_ip、dst_port、proto、duration）、统计特征（4 个，如 src_pkts、dst_ip_bytes）、用户中心特征（DNS 8 个、SSL 6 个、HTTP 11 个）、违规特征（3 个，如 weird_name）[page 20–24]。加上 label 和 type 两个标签属性，共 46 个字段 [page 24]。标签过程是将流标识符和时间戳与每次攻击执行时记录的 IP 和时间戳进行匹配 [page 20]。

## 机器学习验证：高分数背后的条件

第 6 节用四种算法在训练测试集上验证数据集：GBM、RF、Naive Bayes、DNN。结果显示 GBM 的 AUC 达到 0.982945，精确率、召回率、F1 等均超过 0.99 [page 26]；RF 略优于 GBM [page 27]；NB 的 AUC 为 0.912804，表现最低 [page 27]；DNN 介于 RF 和 NB 之间 [page 28]。

但作者自己明确指出了这些高分数的条件：实验只用了完整数据集的一小部分（Train_Test_Network_dataset，461,043 条记录，而完整数据集有 22,339,021 条记录），并且保留了源/目的 IP 地址和端口 [page 24–25]。作者建议研究者在开发新算法时移除 IP 和端口，并使用完整数据集，因为"移除 IP 地址和端口……将展示该数据集中安全事件的复杂性，并降低机器学习算法的性能" [page 24]。这是一个重要的自我限定：当前报告的高性能不能直接外推到更现实的评估设置。

完整数据集的类别分布极不均衡：normal 796,380 条，而 scanning 7,140,161 条、DDoS 6,165,008 条、DoS 3,375,328 条、XSS 2,108,944 条、password 1,718,568 条，而 MITM 仅 1,052 条 [page 25]。训练测试集则被人工平衡为每类约 20,000 条（MITM 除外，1,043 条；normal 300,000 条）[page 25]。这种平衡处理使得训练测试集上的结果不能代表原始分布下的检测难度。

## 与既有数据集的比较：优势与未言明的边界

表 9 从七个维度比较了 TON_IoT 与 15 个既有数据集：真实网络配置、真实网络流量、标注观测、异构数据源、全交互捕获、全包捕获、多恶意场景 [page 30]。TON_IoT 在全部七个维度上标注为 True，是表中唯一做到这一点的数据集。作者特别强调，N-BaIoT 和 Bot-IoT 虽然针对 IoT 环境，但不包含 IoT 遥测数据，而 TON_IoT 的四类异构数据源是其独特之处 [page 31]。

这个比较的论证力度取决于比较维度的选择。作者选择的七个维度确实覆盖了其数据集的核心特征，但论文没有讨论数据集的规模是否足以训练深度模型、攻击场景是否覆盖了真实 APT 的长期潜伏行为、以及测试床的虚拟化环境在多大程度上能代表物理 IoT 部署。这些是论文未讨论的限制，不应被读作作者的结论。

## 结论成立的条件

综合来看，论文的结论——TON_IoT 是一个具有异构数据源、可信标签和多样攻击场景的 IoT 安全数据集——在以下条件下成立：测试床的虚拟化架构确实能产生与物理 IoT 网络足够相似的流量模式（论文通过使用真实协议和工具来支持这一点，但未做定量验证）；攻击时间戳与日志时间戳的对齐足够精确（论文描述了方法但未报告误差）；以及 44 个 Zeek 特征足以支撑作者列举的多种安全应用（论文展示了二分类和多分类的可行性，但未验证隐私保护、威胁情报等应用）。

作者在结论中承认，机器学习的高输出"反映的是数据集小部分在二分类问题上的性能" [page 31]。这是一个诚实的限定。对于想要使用该数据集的研究者，论文给出的最有用建议或许是：移除 IP 和端口，使用完整数据集，并预期性能会显著下降——这恰恰是该数据集声称的"复杂性"所在。

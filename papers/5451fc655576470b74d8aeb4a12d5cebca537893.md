# 让机器读懂网页：语义网的主张、证据与边界

**原文题名：** The Semantic Web
**作者：** Tim Berners-Lee、James Hendler、Ora Lassila
**年份：** 2001
**DOI：** https://doi.org/10.1038/scientificamerican0501-34

## 一个关于"代理"的设想，而非一项已完成的工程

这篇文章的写法很特别：它不从技术定义开始，而是先讲了一个故事。Pete 和 Lucy 要为母亲安排理疗，他们的软件代理自动检索处方、筛选保险网络内的诊所、比对兄妹俩的日程、协商预约时间，最后给出方案 [page 3]。作者随即点明，这个故事之所以可能，靠的不是今天的万维网，而是它将要演化成的"语义网"（Semantic Web）[page 3]。

这个开篇决定了全文的论证性质。作者不是在报告一项已建成的系统，而是在论证一个方向：**当前网页的内容是给人读的，不是给程序处理意义的；如果给网页补上机器可处理的语义，软件代理就能替用户完成复杂任务。** 全文的核心结论可以概括为三层：语义网是现有 Web 的扩展而非替代；实现它需要一套能同时表达数据和推理规则的语言；这套语言的关键构件是 XML、RDF 和本体（ontologies），再辅以数字签名和证明交换 [page 3][page 7][page 9]。

需要说明的是，文章对未来的描述（Pete 和 Lucy 的场景、微波炉查询食品厂商网站等）是**设想性例证**，不是实验结果。作者用它们来说明技术方向，而非证明技术已经实现。读者在评估时应当把"设想"和"已建成"分开。

## 从"关键词无意义"到"三元组有意义"

论证的起点是一个诊断。作者指出，今天的网络搜索会返回大量无关结果，因为计算机不知道"cook"指的是厨师、烹饪方法，还是一个人名 [page 4]。问题的根源是：**词对计算机没有语义内容。** 这个诊断是全文要解决的目标问题。

接着作者给出解决方案的技术路径。第一步是 XML：它允许任何人自定义标签，比如 `<zip code>` 或 `<alma mater>`，从而给文档加上任意结构。但作者明确指出 XML 的局限——它"对结构的意义什么也没说"，脚本作者必须事先知道页面作者用每个标签做什么 [page 5]。这是一个关键的中间结论：**仅有结构不够，还需要表达意义。**

意义由 RDF 表达。RDF 把信息编码成一组"三元组"，每个三元组类似简单句的主语、动词、宾语。主语和宾语用 URI（统一资源标识符）标识，动词也用 URI 标识，因此任何人都能通过在某处定义一个 URI 来引入新概念 [page 7]。作者用"小丑送气球"的例子说明为什么需要为每个具体概念使用不同 URI：如果"地址"既指账单寄送地址又指街道地址，代理就会把气球送到邮局 [page 7]。这一步的推理是：**歧义对人类语言是常态，对自动化是灾难；URI 通过唯一标识消除歧义。**

但 RDF 本身还不够。两个数据库可能用不同标识符指称同一个概念（如 zip code 与 postal code）。于是引入第三个构件——本体。本体是形式化定义术语间关系的文档，通常包含一个分类体系（taxonomy）和一组推理规则 [page 7]。分类体系定义对象的类别及关系，推理规则则允许程序推导新事实。作者举例：如果城市代码关联州代码，而某地址使用该城市代码，那么该地址就具有关联的州代码；程序由此可推断康奈尔大学的地址在纽约州、属于美国，应按美国格式处理 [page 7]。

这里有一个值得注意的推理转折。作者承认，本体之间也可能冲突（一个定义 address 含 zip code，另一个用 postal code），解决办法是本体提供等价关系 [page 8]。也就是说，**语义网不追求全局一致，而是允许局部本体通过等价声明逐步连接。** 这与作者反复强调的"去中心化"原则一致：Web 当年放弃了完全一致的互联理想，换来了不受约束的指数增长 [page 4]。

## 代理、证明与签名：从"能读懂"到"能信任"

技术构件讲完后，作者转向它们能支撑什么。核心主张是：语义网的真正力量在于让大量程序从不同来源收集内容、处理信息、交换结果 [page 9]。代理的有效性会随机器可读内容和自动化服务的增加而"指数级"提升——即使不是为协同工作而设计的代理，只要数据带语义，也能互相传递数据 [page 9]。

这里有两个支撑性机制值得单独提出。一是**证明交换**：代理用统一语言写出推理证明，接收方的推理引擎可以验证 [page 9]。作者说，一些程序已经能用统一语言的初步版本交换证明，但"仍远未触及语义网潜力的深处" [page 9]。二是**数字签名**：加密数据块，用于验证信息来自特定可信来源。作者强调代理应当对读到的断言保持怀疑，直到核实来源 [page 9]。

这两个机制共同支撑一个更强的结论：语义网不只是让机器"读懂"数据，还要让机器**判断该不该相信**数据。这是从"语义"到"可信自动化"的关键一步。作者没有展开证明交换和数字签名的具体技术细节，因此这一步的论证强度依赖于读者对这两个机制可行性的接受。

## 服务发现：语义方案相对结构化方案的优势

作者用一段对比来强化论证。已有的自动化服务发现方案，如微软的 Universal Plug and Play（侧重连接设备）和 Sun 的 Jini（侧重连接服务），都是在"结构或语法层面"解决问题，严重依赖对预定功能描述的标准化 [page 9]。作者的反驳是：标准化只能走到一定程度，因为我们无法预知所有未来需求 [page 9]。

语义网的方案不同：消费者和生产者的代理可以通过交换本体达成共识，本体提供讨论所需的词汇；代理甚至能在发现新本体时"自举"新的推理能力 [page 9]。作者还指出，语义让利用"只部分匹配请求"的服务变得更容易 [page 9]。这一段是全文少见的直接技术对比，其推理是：**标准化预设了功能集合，本体则允许功能描述在使用中动态协商。** 这个对比支撑了"语义网更灵活"的主张，但作者没有给出两种方案在实际部署中的性能或覆盖率数据，因此这仍是设计理念层面的论证。

## 结论成立的条件与作者承认的边界

作者对语义网的边界有若干明确交代，这些交代决定了结论在什么条件下成立。

**第一，逻辑表达力需要权衡。** 作者承认，语义网研究者接受悖论和不可回答问题作为"实现通用性必须付出的代价" [page 5]。规则语言要足够表达力强以描述复杂属性，但不能强到让代理被悖论欺骗 [page 5]。作者引用哥德尔定理的精神：任何足够复杂因而有用的系统都包含不可回答的问题 [page 5]。这意味着语义网不承诺解决所有查询，只承诺在可处理的范围内提供推理能力。

**第二，去中心化意味着放弃完全一致。** 作者明确说，去中心化需要妥协，Web 当年就放弃了所有互联完全一致的理想，带来了"Error 404: Not Found" [page 4]。语义网继承这一取舍：本体之间可能冲突，需要通过等价关系逐步解决，而非由中央权威统一 [page 8]。

**第三，代理需要额外技术。** 作者指出，要自动按需创建复杂的价值链，有些代理还需要利用人工智能技术，语义网只是提供基础和框架 [page 10]。这等于承认语义网本身不构成完整的自动化解决方案。

**第四，部分能力仍是设想。** 设备自动寻找服务、微波炉查询食品厂商网站等场景，作者用"不难想象"引出 [page 10]，属于展望而非已验证的结果。CC/PP 标准（Composite Capability/Preference Profile）被描述为"最初"用于让手机等非标准客户端描述特征 [page 10]，说明这一方向当时尚在起步。

## 论证的整体走向

把全文串起来看，作者的论证是一条从诊断到方案再到愿景的链条：当前 Web 的内容对机器无意义（诊断）→ 需要同时表达数据和规则的语言（目标）→ XML 提供结构、RDF 提供意义、本体提供推理（方案）→ 代理、证明、签名、服务发现使自动化成为可能（应用）→ 语义网还能辅助人类知识整体的演化（更远的愿景）[page 3][page 5][page 7][page 9][page 10]。

其中最关键的一步推理是：**意义的表达可以分解为"用 URI 唯一标识概念"加"用本体定义概念间关系"加"用规则推导新事实"。** 这一步之所以关键，是因为它把"让机器理解意义"这个看似需要人工智能的问题，转化为一个工程问题——只要概念有唯一标识、关系有形式定义、规则可被程序执行，机器就能在不需要真正"理解"的情况下有效操作术语 [page 7]。作者自己说得很清楚：计算机并不真正"理解"这些信息，但能以对人类用户有用且有意义的方式更有效地操作术语 [page 7]。

这个转化是全文论证的支点，也是它最需要被检验的地方。它成立的条件是：概念确实能被 URI 唯一标识、本体确实能被广泛共享和连接、规则确实能在不引发悖论的前提下足够表达。作者对这三个条件都有所讨论，但都停留在设计原则和初步演示层面。文章发表于 2001 年，其价值在于提出了一个清晰的技术方向和一套可操作的构件划分，而非证明这条路径必然成功。读者若把它当作已完成的蓝图，就超出了文本本身能支撑的范围。

# OpenSesame：一个面向社会科学的开源图形化实验构建器

**原文题名：** OpenSesame: An open-source, graphical experiment builder for the social sciences（2011，DOI: 10.3758/s13428-011-0168-7）

## 一、作者要证明什么

这篇论文本质上是一篇软件介绍性文章，但它并非单纯的功能罗列，而是围绕一个核心主张展开：**OpenSesame 填补了一个此前未被满足的生态位——一个既免费、开源、跨平台，又提供完整图形化界面（GUI）的实验构建工具** [page 1]。作者进一步主张，这一工具在时间精度上足以胜任即使最苛刻的时间敏感实验 [page 10]。

要理解这个主张的分量，需要看作者如何界定现有软件的格局。论文开篇引用 Schneider (1988) 的估计——专业程序员实现一个新实验范式约需 160 小时——以此说明实验软件的历史痛点，并指出如今"点击式"软件包已大幅降低了门槛 [page 1]。但作者随即指出一个关键缺口：当时至少有八个免费软件包可用于构建实验（Table 1, [page 2]），然而它们"占据的生态位相对狭小，主要因为它们不提供许多用户已经习惯的那种完全图形化界面" [page 1]。换言之，免费软件要么需要编程（如 DMDX、PsychoPy 的库、Vision Egg），要么界面不完整；而拥有成熟 GUI 的软件（E-Prime、Presentation、Inquisit、DirectRT）几乎都是专有付费的。OpenSesame 的定位正是这个交叉点：**免费 + 开源 + 跨平台 + 完整 GUI + 可选 Python 脚本**。

## 二、功能主张如何被支撑

作者对功能的论证主要依赖描述与对照，而非量化实验。GUI 的核心设计是"项目（item）"模型：实验被表示为树状结构（Fig. 1b, [page 3]），用户从工具栏拖拽项目到概览区，共 10 个核心项目（Table 2, [page 4]）覆盖结构控制（loop、sequence）、刺激呈现（sketchpad、feedback、sampler、synth）、反应收集（keyboard_response、mouse_response）、数据记录（logger）和内联脚本（inline_script）。

这里有一个值得注意的论证转折：作者承认"设计 GUI 时最大的挑战之一就是提供足够的灵活性" [page 3]。他们的解决方案是变量与条件语句。变量可以内建（如 subject_nr）、由项目设置（如 response_time）、或由用户在 loop 中指定；通过在字段中输入 `[variable_name]` 即可调用，例如用 `[SOA]` 控制 sketchpad 的呈现时长（Fig. 2b, [page 4]）。条件语句则通过每个项目的 "Run if" 参数实现，例如 `[correct]=1` 只在反应正确时调用某项目（Fig. 2d, [page 4]）。作者还特别强调 sketchpad 绘图工具与变量结合的力量：绘图工具自动生成脚本行，用户可将静态值替换为变量，从而"以直观的方式创建灵活的刺激呈现" [page 3]。这一设计是"图形化"与"可编程"之间的桥梁，也是作者论证 GUI 足以应对复杂范式的关键一步。

对于 GUI 确实无法覆盖的场景，作者提供了 Python 内联脚本作为兜底 [page 5]，并给出选择 Python 而非 E-Basic 的理由：Python 拥有大量面向科学界的库 [page 6]。此外，插件机制（plug-ins）允许第三方扩展功能，且从用户视角看，插件与内置项目"几乎没有区别" [page 5]。后端层（back-end layer）的独立性则允许在 PyGame、PsychoPy、OpenGL 之间切换（Table 3, [page 6]），作者称这是为了实现与现有软件的互操作性——例如选择 psycho 后端后，用户可在实验中直接使用 PsychoPy 的例程 [page 10]。

## 三、与 E-Prime 和 PsychoPy 的对照

作者选择这两个软件作重点比较，理由是它们与 OpenSesame"共同点最多" [page 6]。与 E-Prime 的差异被归纳为四点：开源 vs 专有、跨平台 vs 仅 Windows、Python vs E-Basic、以及插件框架带来的可扩展性 [page 6]。与 PsychoPy 的比较更为微妙：两者都是开源、跨平台、都同时提供 GUI 和 Python 库，但作者指出 GUI 的侧重点不同——PsychoPy 的 builder view 展示时间进程但不直观呈现刺激的空间排布，而 OpenSesame 通过 sketchpad 提供视觉预览 [page 6]。作者据此推断两者的目标受众不同：PsychoPy 面向偏好编码的用户（如寻找开源替代的 MATLAB 用户），OpenSesame 面向"主要在图形环境中工作"的用户 [page 7]。值得注意的是，作者并未将两者对立，而是强调可以组合使用，以取得"两全其美"的效果 [page 7]。

## 四、时间精度：论证的关键一步

论文最具实证分量的部分是关于时间精度的论证。作者首先重新定义了"毫秒精度"的衡量方式：**最佳指标是刺激呈现时间戳与反应时间戳之间的间隔，前提是使用一个尽可能快、且不属于系统本身的外部反应者** [page 7]。其逻辑是：显示呈现和反应收集中的任何不准确都会累加到最低可能反应时上；更重要的是，这个最低反应时应当**一致**，使延迟成为固定值而非噪声来源 [page 7]。

作者随后列举了系统之外的限制因素：普通键盘延迟可达 20 ms 且可变（但作者引用 Damian, 2010 指出，相对于人类反应时的更大变异性，这是否构成显著噪声仍有争议）[page 7]；显示器逐行刷新，100 Hz 下顶部与底部刺激可相差 10 ms，且刺激间隔只能是刷新周期的整数倍 [page 7]。这些讨论为后文的基准实验设定了合理的期望边界。

在软件层面，作者描述了"prepare–run 策略"：每个 sequence 中的项目被调用两次，prepare 阶段完成耗时操作（如生成声音、构建离线画布），run 阶段只执行极少量的平凡函数 [page 7]。作者明确说明这一策略实现在 sequence 层级，且 loop 整体不被 prepare，因为那样会"迅速导致内存过度使用，并可能引发而非防止时间问题" [page 7]。这是一个作者主动交代的设计权衡。

基准实验使用了一个通过光敏电阻对白光呈现做出反应的人工反应者，测量对白色显示的反应时 [page 8]。方法上有一个值得注意的细节：作者强调实验"完全用 GUI 创建，没有使用任何 Python 内联代码"，以确保结果"现实（即未为优化性能而调整）" [page 8]。测试覆盖两台系统、三种分辨率/刷新率组合、三种后端，每次收集 1,000 个反应（Table 4, [page 8]）。

结果（Fig. 4 与 Table 4, [page 8–9]）显示：硬件加速后端（psycho、opengl）的反应时在 Windows XP 上始终低于 4 ms，在 Ubuntu Linux 10.04 上低于 2 ms；而 legacy 后端明显更慢（Windows 上 9–16 ms，Linux 上约 3.3–3.6 ms），且在 Ubuntu 上未启用垂直刷新同步 [page 10]。作者据此得出结论：**对时间敏感的实验，建议使用硬件加速后端**，其可忽略的延迟"即使在最苛刻的时间敏感实验中也应可接受" [page 10]。作者还附带指出，数据未显示显示模式对性能有影响，因为准备大画布的开销被隐藏在 prepare 阶段 [page 10]。

## 五、结论成立的条件与边界

这篇论文的结论有若干明确的适用条件，读者需要留意：

**平台与后端依赖。** 时间精度的结论明确绑定于硬件加速后端。legacy 后端在 Ubuntu 上未启用垂直同步，其数据不应被用来支持"毫秒精度"的主张 [page 10]。此外，Mac OS 包在写作时被标注为"实验性"，尚待进一步测试 [page 2]。

**基准实验的推断性质。** 作者自己承认，包含的测试实验依赖"计算机的自我报告"，这可能具有误导性——计算机可能报告显示已呈现，而实际上只是排队等待 [page 8]。基准实验正是为绕开这一局限而设计的外部测量。但需注意，该实验测量的是"最低可能反应时"这一特定指标，作者将其作为综合时间精度的度量，这一推理依赖于两个假设：显示呈现的不准确总是使实际呈现晚于报告时间，反应的不准确总是使报告时间晚于实际反应 [page 8]。作者明说了这两个假设，读者应将其视为结论成立的前提。

**未做统计推断。** 作者明确表示"未进行进一步统计，因为数据本质上是描述性的" [page 10]。因此 Table 4 中的均值与标准差应被理解为描述性汇总，而非经过推断统计检验的组间差异。

**硬件与实验类型的边界。** 作者指出处理能力需求"强烈依赖于实验类型"，典型实验需求很低（甚至可在低端上网本上运行），但使用高清视频等复杂刺激时，用户需自行评估系统是否胜任 [page 2]。键盘延迟、显示器刷新特性等系统外因素也构成精度上限 [page 7]。

**OCR 疑点。** 提取文本中 Table 4 出现 "85 Gz"（应为 85 Hz）以及 "ATI Radeon EA H4350"、"Llyama vision master pro 454" 等疑似 OCR 讹误 [page 8]。这些不影响主要论证方向，但涉及具体硬件型号时应以原文为准。

## 六、整体评价

这篇论文的论证结构是"定位缺口—展示功能—对照竞品—实证精度—总结优势"。其最有说服力的部分是基准实验：通过外部人工反应者绕开自我报告的局限，用最低可能反应时这一可操作指标，将"毫秒精度"从模糊宣称转化为可比较的数值。其最需要读者保持审慎的部分，是功能与竞品比较中大量依赖作者自身经验与判断的表述（如"arguably offers the most intuitive and comprehensive GUI" [page 1]），这些是作者的主张而非实验结论。总体而言，论文成功地论证了 OpenSesame 在"免费开源 + 完整 GUI + 跨平台"这一组合上的独特性，并以可复现的基准数据支撑了其时间精度足以用于时间敏感实验的主张——但这一精度主张的成立，严格依赖于使用硬件加速后端以及满足前述各项系统与假设条件。

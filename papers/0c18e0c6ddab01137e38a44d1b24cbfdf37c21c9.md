# ZINC20：面向配体发现的超大规模免费化学数据库——论证分析

**原文题名**：ZINC20—A Free Ultralarge-Scale Chemical Database for Ligand Discovery（2020）
**DOI**：https://doi.org/10.1021/acs.jcim.0c00675

## 一、作者要解决的核心问题

这篇论文的主张可以拆成两条相互支撑的线索。第一条是**资源性主张**：ZINC20 收录了约 14 亿化合物（其中 13 亿可购买），并且以"按需合成"（make-on-demand）库为主体的可购买化学空间，在分子数量、骨架多样性和形状多样性上都远超传统实体库 [page 3]。第二条是**方法性主张**：面对这种规模，传统基于指纹（fingerprint）的检索已经无法维持"实时"体验，作者用两种新算法——SmallWorld（整体分子相似性）和 Arthor（子结构与模式匹配）——把检索重新拉回实时或近实时区间 [page 5–7]。

两条线索合起来构成论文的最终结论：**全枚举（fully enumerated）数据库在原子级精度上仍具不可替代的优势，而新算法使这种精度在数十亿乃至上百亿分子规模下依然可用** [page 7–8]。

## 二、从证据到结论：多样性论证

作者首先用规模数据建立背景：ZINC20 含 14 亿化合物，13 亿可购买，来自 150 家公司的 310 个目录，并遵循"90/90/90 规则"（90% 目录每 90 天刷新，90% 化合物在近三个月内验证可购买）[page 3]。全球实体库存约 1400 万，年增长仅几个百分点；而按需合成库近乎指数增长，目前已超过 $10^{10}$ 名义可用，作者预计数年内可达 $10^{11}$–$10^{12}$ [page 1]。

多样性的核心证据是 Bemis–Murcko 骨架分布（Figure 2, Table 1, Table 2）。作者比较了 ZINC 按需合成库（主要来自 Enamine REAL）与三个实体库：MLSMR、SMDC 和 ZINC "in-stock" Ro4 集合。关键数字是：按需合成库的分子数比 in-stock 库多 **88 倍**，但骨架数只多 **16 倍** [page 3, page 8]。这个不对称比例是论证的枢纽——它说明按需合成库并非简单地把同一批骨架堆满，而是确实引入了大量新骨架。

更直接的证据在 Table 2 [page 4]：MLSMR 的 108,178 个骨架中有 99.9% 不在按需合成库中；SMDC 为 99.8%；in-stock Ro4 为 97.5%。反过来，按需合成库的骨架在实体库中几乎无代表。作者据此说"几乎所有按需合成分子在骨架层面都没有实体库对应物" [page 4]。

形状多样性用 NPMI（归一化主惯性矩比）刻画（Figure 3）[page 4]。作者把分子分为棒状（rod，1D）、盘状（disc，2D）和球状（sphere，3D），并给出参照物：苯为盘状（npr1 = 0.5, npr2 = 0.5），金刚烷为球状（npr1 = 1, npr2 = 1），格列卫为棒状（npr1 = 0, npr2 = 1）。结论是按需合成库在球状区域（右上角）的覆盖远密于实体库，而实体库历来偏向棒状、其次盘状 [page 4, page 8]。

**这里的关键推理步骤**是：骨架数和形状分布这两个独立指标都指向同一方向——按需合成库的多样性不是规模膨胀的副产品，而是结构上的真实扩展。作者把这一点的来源归因于"构建模块（building blocks）本身的新颖性" [page 8]，即这些砌块此前无法用于枚举库。这是一个因果解释，但论文并未用实验直接验证"砌块新颖性→骨架新颖性"的因果链，而是作为与平行化学事实一致的推断提出（"consistent with"）[page 3]。

## 三、从证据到结论：检索方法论证

作者先建立"实时性"的操作定义：可靠地在 1 分钟内返回结果为实时，超过 3 分钟则失去研究者即时注意力，1–3 分钟为近实时 [page 2]。这个定义是主观经验性的，作者明确说"individuals vary"且"our own experience" [page 2]，因此它是论证的**前提假设**而非客观标准。

问题陈述用具体计时支撑：ECFP4 Tanimoto 40% 相似性检索，1 亿分子在 64 核机器上通常 20 秒内完成，10 亿分子则常超过 3 分钟 [page 1]。子结构和模式检索更糟，即便在 1 亿分子规模也常无法在 3 分钟内完成 [page 2]。作者还指出相似性检索的一个本质困难：要保证找到最相似分子，必须扫描整个数据库，不完整扫描可能给出误导结果 [page 1–2]。这一点很重要，因为它解释了为什么相似性检索不能像子结构检索那样"部分完成也有用"。

SmallWorld 的机制是图编辑距离（graph-edit distance）加最大公共子图（MCS），其关键创新是**预索引匿名图**（anonymous graphs）：检索时只需查找目标分子的匿名图，再在图编辑距离空间中做小步遍历（Figure 4）[page 5]。作者列出六种基本编辑步骤：加末端原子（tup）、删末端原子（tdn）、开环（rup）、闭环（rdn）、插入连接原子（lup）、删连接原子（ldn）[page 5]。由此检索时间呈**亚线性**增长，几乎与分子数无关（前提是有足够大且快的磁盘存放索引）[page 5]。证据是：在 1660 亿分子的数据库中，最相似分子通常 1–2 秒内找到 [page 5–6]。

Arthor 则用紧凑的持久二进制表示和基于 SMARTS 的定制模式匹配器 [page 6]。在至少 128 GB 内存下，10 亿分子的子结构或模式检索约 1–2 秒 [page 6]。与 SmallWorld 不同，Arthor 性能随数据库增长**大致线性** [page 6, page 8]。作者用 RoundTable 算法把它扩展到多机阵列以支持数十亿分子 [page 6]。

**关键对照**在 page 6：对 515 万（原文写 515 million，即 5.15 亿）按需合成分子做类似物检索，SmallWorld 通常数秒内出首批结果，数千个类似物通常 15 秒内出现；而旧的 ECFP4-Postgres 方法检索 14 亿分子找最相似 100 个类似物几乎总要超过 3 分钟。作者称这是"radical and profound improvement" [page 6]。这个对照是方法性主张最直接的证据。

## 四、论证中的桥接与省略

作者从"SmallWorld 亚线性"跳到"可支撑未来数个数量级的库增长" [page 7–8]，这一步依赖一个未明说的桥接：亚线性检索时间的前提是索引能装进足够快的磁盘，而索引本身随分子数增长。作者在 Methods 中给出索引密度：SmallWorld 匿名图索引约 1300–1400 万分子/GB，42 TB 索引对应约 1660 亿分子规模 [page 8]。因此"亚线性"指的是**检索时间**，不是**存储成本**。作者在讨论局限时承认硬件成本达数十万美元、每月需数百人时维护 [page 8]，但没有明确说存储增长是否会先于检索时间成为瓶颈。这是分析者基于文本的推断，非作者原话。

另一个桥接是"按需合成库可购买"这一前提。作者用自身经验支撑：十多个项目中合成履约率超过 85%，与所谓现货化合物相当 [page 1]。Box 1 给出可购买性分级（Premier、In-stock、Agent、On-demand、Boutique、Annotated），并说明 On-demand 通常约 100 美元、一般低于 200 美元、约六周交付、85% 交付成功率 [page 6]。这些是经验数据，非对照实验。

## 五、结论成立的条件与边界

作者明确承认的局限有几点 [page 8]：

其一，**数据库是移动目标**。每月超过 2 万个按需合成化合物转为现货，约四分之一现货售罄；按需合成库增减更快，曾见单月新增 $10^9$ 分子，也常见数亿分子因供应商发现难以合成而被重新归类为不可用。这意味着任何基于某一时点快照的多样性统计都可能迅速过时。

其二，**Arthor 线性扩展的长期问题**。作者直言，数量级更多的分子需要数量级更多的内存和/或 CPU，这会迅速成为限制；并呼吁"类似 SmallWorld 的亚线性子结构/模式匹配算法" [page 8]。这是作者主动指出的方法边界。

其三，**公开服务的人为限制**。Arthor 公开检索上限 10,000 分子，超过则结果不完整 [page 6–7]。作者说明这是"pragmatic fashion"的取舍，并计划在算力增加后上调。

其四，**Bemis–Murcko 骨架作为分类器的弱点**。作者指出最过度代表的骨架往往是小而简单的，如苯基（350 万）、吡啶（280 万）、环己基（170 万），反映"用 Bemis–Murcko 骨架分类这些超小骨架的弱点" [page 3]。这削弱了骨架计数作为多样性唯一指标的可靠性，但作者仍将其作为主要证据之一。

其五，**相似性检索的完整性要求**。作者在 page 2 指出相似性检索必须扫描全库才能保证找到最相似分子，这与子结构/模式检索"部分完成也有用"形成对比。SmallWorld 的亚线性是否在所有查询下都保证完整性，论文未展开；作者只说"always faster and complete for the closest analogs"（在讨论为何不用 Arthor 做相似性时）[page 7]，但未给出完整性证明。

## 六、术语与数值说明

- **Ro4 / Ro5**：类先导化合物规则，分子量 < 400 g/mol 且计算 logP < 4（Ro4）；Ro5 为更宽松的类药规则 [page 3]。
- **NPMI**：归一化主惯性矩比，npr1 与 npr2 两个比值用于形状分类 [page 4, page 8]。
- **ABC**：analog-by-catalog，基于分子相似性原理在目录中找类似物 [page 2]。
- **SMARTS**：描述分子模式的语言 [page 2, page 6]。

数值疑点：page 6 写"515 million"按需合成分子，而 Table 1 写 ZINC Ro4 make-on-demand 为 515,000,000，Table 2 写 On-Demand 为 531,645,834。两处数字不一致（515M vs 531.6M），可能是不同时点或不同子集，作者未说明。分析中应保留这一不确定性，不将其作为精确前提。此外 page 8 写"109 new molecules appear in a single month"，从上下文（数亿分子被重新分类）看疑为 $10^9$ 的 OCR 或排版问题，但无法从文本确证，故不据此下结论。

## 七、总体评价

论文的论证结构是：**规模增长 → 传统方法失效 → 新算法恢复实时性 → 全枚举库的原子级精度得以保留**。多样性论证（骨架、形状）与方法论证（SmallWorld 亚线性、Arthor 线性但快）相互独立，共同支撑"按需合成库是新的、可检索的、可购买的化学空间"这一结论。结论的强度受限于：实时性定义的主观性、多样性统计的时点依赖、Arthor 线性扩展的长期不可持续性，以及公开服务的 10,000 结果上限。作者对这些局限的承认是明确的，因此论文的贡献应理解为**在特定规模区间（数十亿至上百亿分子）和特定硬件条件下，全枚举原子级检索仍可行的工程性论证**，而非对所有未来规模的普适承诺。

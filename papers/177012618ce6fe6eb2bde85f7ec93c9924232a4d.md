# 把程序变成可学习的向量：SySeVR 如何用深度学习检测软件漏洞

**原文题名：** SySeVR: A Framework for Using Deep Learning to Detect Software Vulnerabilities
**作者：** Zhen Li, Deqing Zou, Shouhuai Xu, Hai Jin, Yawei Zhu, Zhaoxuan Chen
**年份：** 2021（arXiv 版本 v3，2018 年首次提交）
**DOI/来源：** IEEE Transactions on Dependable and Secure Computing；arXiv:1807.06756v3

## 论文要解决的核心难题

软件漏洞层出不穷，而现有的源代码静态检测方法各有短板：基于代码相似性的方法只能发现代码克隆导致的漏洞，对非克隆漏洞漏报率很高；基于模式的方法需要人类专家手工定义漏洞特征，既费力又容易出错 [page 1]。深度学习的吸引力在于它能自动学习特征，但作者指出存在一个"领域鸿沟"：深度学习天生处理的是图像像素、自然语言词向量这类天然具有向量表示的数据，而程序代码没有这样的向量表示 [page 1]。

因此，论文的核心问题不是"深度学习能不能检测漏洞"，而是更基础的一步：**如何把程序表示成既保留漏洞相关语法与语义信息、又能作为神经网络输入的向量？** 作者提出的 SySeVR 框架（Syntax-based, Semantics-based, and Vector Representations）就是围绕这个问题构建的。它是对作者此前工作 VulDeePecker 的系统性扩展，后者只处理库/API 函数调用相关漏洞、只利用数据依赖语义、只用 BLSTM 一种网络、且不解释误报漏报原因 [page 1]。

## 从"区域提议"到"漏洞候选"：框架的基本思路

SySeVR 的灵感来自图像处理中的"区域提议"（region proposal）概念。在图像中检测人，可以提取多个区域提议，每个区域提议作为一个训练单元 [page 2]。但作者明确指出，直接把函数当作区域提议太粗——检测器不仅要判断函数是否有漏洞，还要定位漏洞位置；把单条语句当作单元又太细——大多数语句不含漏洞，且语义相关的多条语句没有被当作整体考虑 [page 2]。

于是框架采用两级候选机制：

**第一级是 SyVC（语法漏洞候选）。** 漏洞往往表现出某些语法特征，比如函数调用、指针使用。SyVC 就是匹配了某种漏洞语法特征的代码元素，它可以是 AST 上的一个叶节点（一个 token），也可以是内部节点（一条语句或多个连续 token）[page 3-4]。作者用集合 $H = \{h_k\}_{1 \le k \le \beta}$ 表示漏洞语法特征集，Algorithm 1 描述了从程序 $P$ 中提取 SyVC 的高层流程：为每个函数生成 AST，遍历 AST 找出匹配某个 $h_k$ 的代码元素 [page 4]。

**第二级是 SeVC（语义漏洞候选）。** SyVC 本身不含语义信息，不足以训练深度模型。SeVC 把 SyVC 扩展为包含语义相关语句的切片。这里的"语义相关"由数据依赖和控制依赖定义，通过程序依赖图（PDG）和程序切片技术实现 [page 4-5]。

## 关键推理的一步：为什么切片能承载漏洞语义

这是整篇论文论证链条中最需要讲清楚的一环。作者的定义层层递进：

先定义 CFG（控制流图），再定义数据依赖（节点 $n_{i,\ell}$ 计算的值在 $n_{i,j}$ 被使用，则 $n_{i,j}$ 数据依赖于 $n_{i,\ell}$）和控制依赖（基于后支配关系定义），然后在此基础上定义 PDG [page 4]。

有了 PDG，就可以从 SyVC 出发做切片。作者同时考虑前向切片和后向切片，理由很直接：(i) SyVC 可能影响后续语句，后续语句可能含漏洞；(ii) 影响 SyVC 的语句可能使 SyVC 变得脆弱 [page 4-5]。Definition 7 给出了前向切片、过程间前向切片、后向切片、过程间后向切片以及程序切片的严格定义。程序切片 $ps_{i,j,z}$ 就是把过程间前向切片和过程间后向切片在 SyVC 处合并，按顺序连接并省略相邻重复节点 [page 5]。

这里有一个值得注意的设计选择：**在计算前向切片时，作者只利用数据依赖，不用控制依赖；而在计算后向切片时，两者都用** [page 6]。作者给出的理由是：受 SyVC 通过控制依赖影响的语句在大多数情况下不会脆弱；如果把控制依赖纳入前向切片，会引入大量与漏洞无关的语句。例如，一个指针变量作为 while 循环条件中的 SyVC，如果循环体内没有引用该指针，那么循环体内的语句只是通过控制依赖受其影响，并不会因此产生漏洞 [page 6]。这个取舍是理解 SeVC 设计意图的关键——它不是要囊括所有语义相关语句，而是要在信息量和噪声之间取得平衡。

Fig. 3 用 SyVC "data"（第 25 行）完整演示了 SyVC→SeVC 的转换：过程间前向切片跨越 func 和 println 两个函数，过程间后向切片与 func 内的后向切片相同（因为没有其他函数调用 func），最终合并得到 SeVC，包含 func 中的 13 条语句和 println 中的 3 条语句，按函数调用顺序排列 [page 5-6]。

## 从 SeVC 到向量：编码与对齐

Algorithm 3 把 SeVC 编码为向量，分三步 [page 6-7]：

1. **符号化**：去除非 ASCII 字符和注释，把用户定义的变量名映射为符号名（如 "V1"、"V2"），函数名映射为 "F1"、"F2"，使 SeVC 独立于具体命名。
2. **向量化**：把符号表示按词法分析拆成符号序列，每个符号转成固定长度向量，拼接得到 SeVC 的向量 $R_{i,j,z}$。
3. **长度对齐**：用阈值 $\theta$ 统一向量长度。短于 $\theta$ 的补零；长于 $\theta$ 的截断，截断策略的核心是让 SyVC 出现在结果向量的中间位置。作者举了一个具体例子：$\theta = 15000$，每个符号长度 30，即每个 SeVC 有 500 个符号；若某 SeVC 有 510 个符号，SyVC 在第 255 个位置，则保留 SyVC 左侧 249 个连续符号和右侧 250 个符号，加上 SyVC 本身，得到 500 个符号的向量 [page 7]。

这个截断策略之所以良定义，是因为每个 SyVC 被转换为一个 SeVC 且在 SeVC 中恰好出现一次 [page 7]。

## 实验设计：四个研究问题与数据集

作者用四个研究问题（RQ1–RQ4）组织实验 [page 7]：

- RQ1：SySeVR 能否让 BLSTM 检测多种（而非单一）类型的漏洞？
- RQ2：SySeVR 能否让多种神经网络检测多种漏洞？能否解释其有效性？
- RQ3：纳入控制依赖能否提升 SySeVR 的效果？提升多少？
- RQ4：SySeVR 方法相比最先进方法效果如何？

数据集来自 NVD 和 SARD 两个来源。从 NVD 收集了 19 个流行 C/C++ 开源产品的 1591 个程序（874 个有漏洞）；从 SARD 收集了 14000 个 C/C++ 程序（13906 个有漏洞）。合计 15591 个程序，其中 14780 个有漏洞，涵盖 126 种漏洞类型（按 CWE ID 标识）[page 7]。评估指标包括 FPR、FNR、准确率 A、精确率 P、F1 和 MCC，其中 MCC 特别适合处理本论文中非漏洞样本远多于漏洞样本的不平衡情况 [page 7-8]。

## 语法特征的提取：一个务实的替代方案

作者坦承，从漏洞程序中提取脆弱代码行并分析其语法特征是一项极其耗时的任务。因此他们采用了一个替代方法：利用商业工具 Checkmarx 的 C/C++ 漏洞规则来推导漏洞语法特征 [page 8]。这个选择需要读者注意其性质——它不是从漏洞数据中直接学习特征，而是借用现有工具的规则作为起点。

通过人工检查 Checkmarx 规则，作者归纳出 4 类漏洞语法特征 [page 8]：

- **FC（库/API 函数调用）**：覆盖 811 个函数调用，对应 106 个 CWE ID。
- **AU（数组使用）**：覆盖 87 个 CWE ID。
- **PU（指针使用）**：覆盖 103 个 CWE ID。
- **AE（算术表达式）**：覆盖 45 个 CWE ID。

Fig. 4 的 Venn 图显示这 4 类特征在 CWE ID 覆盖上相互重叠：10 个 CWE ID 仅被 PU 覆盖，39 个 CWE ID 被全部 4 类覆盖，并集为 126 个 CWE ID [page 8]。匹配规则也在 Fig. 5 中具体说明：例如 PU 的匹配条件是标识符声明节点包含字符 '*'，AE 的匹配条件是表达式语句包含 '=' 且右侧有一个或多个标识符 [page 8-9]。

最终从 15591 个程序中提取了 420627 个 SyVC，覆盖 SARD 中 13016 个（93.6%）有漏洞程序 [page 9]。这个 93.6% 的覆盖率是作者用来验证"用 Checkmarx 规则推导语法特征"这一替代方法有效性的关键证据。但作者也明确指出，由于 NVD 不给出漏洞的精确位置，无法计算对 NVD 的覆盖率 [page 9]。

## 语义信息的效果：控制依赖带来多大提升

420627 个 SyVC 对应生成 420627 个 SeVC。作者生成了两套 SeVC：一套只含数据依赖语义，另一套含数据依赖和控制依赖 [page 9]。Table 1 按 SyVC 类型汇总了 SeVC 数量及其中脆弱/非脆弱的分布：总计 56395 个脆弱 SeVC，364232 个非脆弱 SeVC [page 9]。

Table 5 是回答 RQ3 的核心证据。在 FPR 统一设为 2.0% 的条件下，纳入控制依赖后，各模型的 FNR 和 F1 均有显著改善：平均 FNR 降低 30.4%，F1 提升 24.0% [page 11-12]。以 BGRU 为例，仅用数据依赖时 FNR 为 42.3%、F1 为 65.0%；加入控制依赖后 FNR 降至 14.7%、F1 升至 85.8% [page 12]。这个对比直接支撑了 Insight 5：纳入更多语义信息（控制依赖和数据依赖）的模型具有更高的漏洞检测能力。

## 不同网络架构的比较与解释

Table 3 比较了 8 种模型在 4 类漏洞上的表现（FPR 统一为 2.0%）[page 10]。双向 RNN（BLSTM、BGRU）优于单向 RNN（LSTM、GRU），后者又优于 CNN，CNN 优于 DBN 和浅层模型（LR、MLP）。BGRU 取得最佳 F1（85.8%）和 MCC（83.7%）。作者对此的解释是：双向 RNN 能同时利用语句前后文的信息 [page 10]。

Table 4 则展示了一个有启发性的负面结果：当用词袋（bag-of-words）替代 word2vec 生成向量时，浅层模型反而优于深度网络，BGRU 甚至成为表现最差的模型（F1 仅 48.8%）[page 11]。作者的解释是词袋向量没有上下文信息，BGRU 无法捕捉上下文，因而效果很差。这支撑了 Insight 3：分布式表示（如 word2vec）对捕捉上下文信息至关重要，仅以词频为中心的表示是不够的 [page 11]。

## 对 BGRU 有效性的初步解释

作者尝试解释 BGRU 为何有效，这是论文中一个值得关注的探索性部分。他们观察 BGRU 结构中每个时间步在激活层的输出，发现如果时间步 $t'+1$ 的激活层输出显著大于（或小于）时间步 $t'$ 的输出，则该 token 在分类中起关键作用 [page 11]。进一步发现：一些漏报由 token "if" 或其后续 token 引起，因为这些 token 频繁出现在非脆弱 SeVC 中；一些误报由库/API 函数调用及其参数相关的 token 引起，因为这些 token 频繁出现在脆弱 SeVC 中 [page 11]。这支撑了 Insight 4：语法元素在脆弱与非脆弱 SeVC 中的出现频率差异可能导致误报或漏报。

需要指出，这是作者自己承认的"初步努力"（initial effort），且解释深度神经网络有效性本身是一个未解决的开放问题 [page 11]。

## 与最先进方法的对比

Table 6 是回答 RQ4 的核心证据 [page 12]。SySeVR-BGRU 在 FPR 1.4%、FNR 5.6% 的条件下，F1 达到 92.6%、MCC 达到 90.5%，大幅优于 Flawfinder（F1 25.7%）、RATS（F1 13.7%）、Checkmarx（F1 36.1%）、VUDDY（F1 16.4%）和 VulDeePecker（F1 66.6%）。作者指出 VUDDY 以高 FNR 换取低 FPR，因为它只能检测与训练程序中漏洞几乎相同的漏洞；VulDeePecker 效果较差是因为它无法处理 FC 以外的 SyVC 类型，也无法纳入控制依赖语义 [page 12]。

此外，BGRU 在更大训练集（341536 个 SeVC）上比在较小训练集（30000 个 SeVC）上更有效，FNR 降低了 9.1% [page 12]。

## 真实软件产品上的验证

作者将训练好的 SySeVR-BGRU 应用于 4 个软件产品（Libav、Seamonkey、Thunderbird、Xen），每个产品检查 20 个版本，以判断漏洞是否在新版本中被"静默修补" [page 12]。Table 7 列出了检测到的 15 个未在 NVD 中报告的漏洞：其中 7 个是此前未知的，已报告给厂商；另外 8 个已被厂商在新版本中静默修补 [page 12-13]。作者出于伦理考虑未公布 7 个未知漏洞的精确位置。值得注意的是，用于提取语法特征的 Checkmarx 除 Seamonkey 2.35 和 Thunderbird 38.0.1 中的两个漏洞外，其余全部漏检 [page 12]。

## 结论成立的条件与边界

论文在 Section 4 中明确列出了若干限制 [page 12-13]，这些限制直接界定了结论的适用范围：

**语言与对象边界。** 框架仅针对 C/C++ 源代码，可能需要适配才能处理其他编程语言或可执行文件 [page 12]。

**语法特征覆盖不完整。** 4 类语法特征覆盖 SARD 中 93.6% 的漏洞程序，但这一覆盖并不完美，且 SARD 数据可能不代表真实软件产品。未来需要识别更完整的漏洞语法特征 [page 12]。这意味着 SySeVR 对不匹配这 4 类特征的漏洞类型可能无法检测。

**切片粒度。** 检测在切片级别进行，可能无法精确定位到包含漏洞的具体代码行 [page 12]。

**标签质量。** 真值标签通过人工检查 0.6% 的样本生成，自动标注方法可能存在错误标注。作者用分层 5 折交叉验证识别可能误标的样本并人工修正，共人工检查了 2605 个可能误标的样本，修正了 1641 个漏报 [page 9-10]。但作者承认，由于缺乏真值数据集，未来需要研究更有效的自动标注方法 [page 13]。

**单一模型 vs 多模型。** 实验使用单一模型检测多种漏洞，未来应研究针对不同漏洞类型分别定制多个模型与用单一模型检测多种漏洞哪种更有效 [page 12]。

**可解释性有限。** 虽然作者对 BGRU 的有效性获得了一些洞察，但解释深度学习在此场景及更广泛场景中的成功仍需更多研究 [page 13]。

此外，还有一个作者未在限制部分明确讨论、但读者可以从实验设计中注意到的边界：RQ1 和 RQ2 的实验使用 30000 个训练 SeVC 和 7500 个测试 SeVC，而 RQ4 使用 341536 个训练 SeVC 和 79091 个测试 SeVC [page 10, 12]。训练集规模的差异意味着 Table 3 和 Table 6 中 BGRU 的表现不能直接比较——Table 6 中 BGRU 的优异表现部分来自更大的训练集，作者也明确指出了这一点（FNR 降低 9.1%）[page 12]。

## 总体判断

SySeVR 的核心贡献不在于某个单一算法，而在于提出了一套从程序语法特征出发、经语义切片扩展、最终编码为向量的完整流程，使得多种深度神经网络能够应用于切片级漏洞检测。论文的论证链条清晰：语法特征定义候选 → 程序切片注入语义 → 向量编码适配网络 → 实验验证效果。其中最关键的技术判断是前向切片只用数据依赖、后向切片兼用控制依赖这一非对称设计，它直接影响了 SeVC 的信息含量与噪声水平。

实验证据在多个维度上支撑了作者的主张：多种网络架构的比较（Table 3）、有无控制依赖的对照（Table 5）、与最先进方法的对比（Table 6）、以及在真实软件产品上发现 15 个未报告漏洞（Table 7）。但结论的强度受限于上述边界条件——尤其是语法特征覆盖的 93.6% 上限、标签质量、以及 C/C++ 语言的适用范围。论文对 BGRU 有效性的解释是初步的，作者自己也将"解释深度学习为何有效"列为开放问题。

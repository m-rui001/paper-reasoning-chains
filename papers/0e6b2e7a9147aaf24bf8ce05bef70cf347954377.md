# 用遗传算法自动设计图像分类 CNN 架构：CNN-GA 的论证分析

**原文题名**：Automatically Designing CNN Architectures Using Genetic Algorithm for Image Classification
**作者**：Yanan Sun, Bing Xue, Mengjie Zhang, Gary G. Yen, Jiancheng Lv
**发表**：IEEE Transactions on Cybernetics，DOI: 10.1109/TCYB.2020.2983860

## 论文要解决的核心张力

这篇论文的出发点不是"手工设计的 CNN 不够好"，而是一个用户能力与任务需求之间的错配：CNN 的性能高度依赖架构，而当前最优架构（GoogleNet、ResNet、DenseNet 等）都由同时精通 CNN 与具体数据的专家手工设计 [page 1]。熟悉数据的用户未必懂 CNN 架构设计，反之亦然。作者由此提出一个明确的目标——让不具备 CNN 领域知识的用户也能直接获得一个可用的、性能有竞争力的 CNN 架构。

围绕这个目标，作者把已有方法按"用户是否需要手工调参"分成两类：一类是"automatic + manually tuning"（如 Genetic CNN、Hierarchical Evolution、EAS、Block-QNN-S、NSANet），使用时仍需专家介入；另一类是"automatic"（如 Large-scale Evolution、CGP-CNN、NAS、MetaQNN），用户可直接在数据上运行 [page 1]。作者承认前者因额外的人工专业知识往往性能略好，但强调后者的"免调参"特性才是无领域知识用户真正需要的。这一分类是全文比较框架的基石，也决定了后文实验的公平性讨论。

## 主张与支撑结构

论文的核心主张是：CNN-GA 能在不需要用户具备 CNN 或 GA 专业知识的前提下，自动发现性能有竞争力、参数更少、计算资源消耗显著更低的 CNN 架构。这个主张由三条设计贡献支撑，每条都对应一个具体的技术难题：

**可变长编码与配套交叉算子**。传统 GA 常用定长编码，因为交叉算子最初是为等长个体设计的，编码长度必须预先指定；而理想长度应是未知的最优 CNN 深度，预先估计错误会导致无效架构 [page 2]。作者提出可变长编码策略及相应的交叉算子来同时解决这两个问题。编码的具体形式是：个体由若干"skip layer"（两个卷积层加一条跳跃连接）和池化层组成，skip layer 编码两个卷积层的特征图数量（F1、F2），池化层编码池化类型（P1）[page 4-5]。图 3 给出一个具体例子，编码串 "32-64-0.2-64-256-0.8-512-256-256-512" 表示一个深度为 10 的 CNN，其中 (0, 0.5) 区间的数表示 max pooling，[0.5, 1) 表示 mean pooling [page 4]。交叉算子（Algorithm 5）在父代个体上各随机选一点切分，交换片段生成两个后代，从而允许不等长个体间的交叉 [page 7-8]。

**引入跳跃连接**。作者用 skip layer 替代普通卷积层，理由是跳跃连接能缓解梯度消失（Vanishing Gradient, VG）问题，使深层网络可训练 [page 3]。这一设计有两个作用：一是缩小搜索空间，二是使演化出的架构相比同类性能算法更简单 [page 2]。作者明确说明，skip layer 用两个卷积层是受 ResNet 启发，但与之不同的是，本文允许各 skip layer 的特征图尺寸不等，更灵活 [page 5]。

**异步计算与缓存加速**。作者指出，多数已有算法采用数据并行策略，但大多数架构是中等规模，不需要在大量计算节点上运行，否则节点间通信会占据大部分开销 [page 2]。因此设计了异步组件（基于 GPU 的并行计算平台）和缓存组件（存储已评估架构的适应度，避免重复评估）[page 6-7]。缓存用 224-hash 码作为个体标识符，作者论证冲突不会发生（可生成 2^224 个不同标识符，而实际只评估数千个 CNN），且每条记录仅占 37 字节，无需担心缓存大小 [page 7]。

## 从证据到结论的关键推理

实验在 CIFAR10 和 CIFAR100 上进行，对比对象分三类：8 个手工设计 CNN、6 个"automatic+manually tuning"算法、4 个"automatic"算法 [page 9]。表 I 是核心证据 [page 11]。

关键推理链条是：在"automatic"类别内（这是作者认为唯一公平的比较），CNN-GA 在分类准确率上优于 Large-scale Evolution、CGP-CNN、NAS、Meta-QNN；同时参数数量和 GPU days 显著更低。例如 CNN-GA 在 CIFAR10 上用 2.9M 参数、35 GPU days 达到 95.22%，而 Large-scale Evolution 用 5.4M 参数、2750 GPU days 达到 94.60%；NAS 更是消耗 22,400 GPU days [page 11]。作者据此总结：CNN-GA 用平均约 90% 更简单的架构、99% 更少的计算资源，取得了有竞争力的性能 [page 12]。

这里有一个需要读者注意的推理跳跃：作者用"平均"来概括资源节省，其计算方式是把同类竞争者的 GPU days 加总（28,027）除以可用结果数（6）得到平均 4,671，再与 CNN-GA 的平均 37.5 相比 [page 12 脚注 3]。这个平均把 NAS 的 22,400 GPU days 这类极端值纳入，会放大对比效果。作者没有做统计显著性检验，也没有报告多次运行的方差（除最终架构独立训练五次取最优外），因此"99% 更少资源"应理解为量级上的对比，而非精确的统计结论。

与"automatic+manually tuning"类别的比较更能体现作者的自我限定。CNN-GA 在 CIFAR10 上比 Hierarchical Evolution 低 1.15%，比 Block-QNN-S 略差，与 EAS 相当，比 NASNet-B 低约 1% [page 11-12]。作者没有回避这一点，而是强调这些算法都需要人工介入：EAS 需要先在给定数据上手工调好一个 CNN 再精炼；Hierarchical Evolution 和 Block-QNN-S 发现的 CNN 不能直接使用，必须插入预先手工设计的大网络；NASNet 需要提供框架架构并使用未公开的 revised path-dropping 技术 [page 12]。DARTS 虽然性能与参数和 CNN-GA 相近且 GPU days 更少（4 vs 35），但需要一个手工设计的大 CNN 作为构建块，若提供的 CNN 小于最优，DARTS 永远找不到最优架构 [page 12]。这些限定说明：CNN-GA 的"自动"优势是以牺牲部分性能为代价换来的，而作者认为这个交换对目标用户是值得的。

## 结论成立的条件与边界

**"自动"的定义是用户视角的**。作者明确说明，"automatic"与"automatic+manually-tuning"是从用户而非开发者视角讨论的；开发高性能算法仍应鼓励使用充分的领域知识，并以微软设计 Windows 操作系统作类比 [page 2]。这意味着 CNN-GA 的"自动"指的是使用阶段无需专业知识，而非算法本身不含任何先验设计。

**若干关键设置来自作者的专业判断，而非算法自动学习**。卷积操作的 filter 和 stride 固定为 3×3 和 1×1，只用 same 卷积；池化层固定为 2×2 kernel 和 stride；可用特征图数量限定为 {64, 128, 256}；丢弃全连接层 [page 5, 10]。作者承认这些设置部分基于"我们在手工调参 CNN 架构方面的专业知识" [page 5]。因此，算法搜索的是在这些预设约束下的架构，而非完全无约束的架构空间。这是"自动"边界的重要限定。

**适应度评估依赖训练过程**。每个个体用 SGD（学习率 0.1、动量 0.9）训练 350 epochs，学习率在第 1、149、249 epoch 衰减 0.1 [page 10]。适应度是 fitness evaluation set 上的分类准确率，训练集被划分为 90% 训练、10% 评估 [page 10]。这意味着适应度信号本身受训练超参数影响，而这些超参数是固定的、非搜索的。

**比较公平性受训练流程差异限制**。作者承认，由于多个竞争者追求最高准确率，采用了不同的训练流程和数据增强方法（如 NASNet 使用 revised path drop），而该技术未公开，因此 CNN-GA 只保持了与多数竞争者相同的训练流程和增强方法；作者提醒"仅比较分类准确率对本文算法也不公平" [page 11]。这是一个诚实的自我限定，也意味着表 I 中的准确率对比应谨慎解读。

**演化轨迹支持 20 代的设置，但仅限 CIFAR10**。图 5 显示，从第 2 代到第 4 代提升很小，之后急剧上升直到第 15 代，此后变化不大，作者据此认为 20 代的设置在 CIFAR10 上是合理的 [page 12-13]。但这一收敛性证据只针对 CIFAR10，论文未展示 CIFAR100 的演化轨迹，因此不能直接推广到 CIFAR100 或更复杂数据集。

**作者承认的计算资源局限**。结论部分明确指出，虽然设计了两个加速组件节省了大量资源，但消耗的计算资源仍比 GA 解决传统问题大得多；未来工作将聚焦于开发进化计算方法以显著加速 CNN 的适应度评估 [page 13]。这说明"资源消耗低"是相对于同类 CNN 架构搜索算法而言，而非绝对意义上的低。

## 一处需要留意的数值疑点

表 I 中 CNN-GA 在 CIFAR10 上报告 95.22%（无 cutout）和 96.78%（+cutout），CIFAR100 上 77.97% 和 79.47% [page 11]。正文在讨论 HOG+SVM 对比时，把 CNN-GA 的结果写作 96.78% 和 79.47% [page 12]，即使用了 +cutout 的数值。这本身一致，但读者需注意：表 I 中 CNN-GA 的 CIFAR100 无 cutout 结果 77.97% 与 +cutout 的 79.47% 是两个不同配置，正文在总结"CNN-GA 优于手工设计 CNN"时混合引用了不同配置的数值，比较时应区分。

## 总体判断

这篇论文的论证结构是清晰的：先确立"用户无领域知识"这一目标场景，据此把已有方法分类并论证"automatic"类别的价值，再提出三项针对性设计，最后用跨三类竞争者的实验支撑主张。其最有说服力的部分是在"automatic"类别内的对比——CNN-GA 在准确率、参数、GPU days 三个维度上同时占优，且资源节省达到量级差异。其结论的边界也相对诚实：作者主动承认"automatic+manually tuning"类算法性能略好、比较公平性受训练流程差异限制、计算资源仍偏大。读者若要把结论用于实践，需要记住：CNN-GA 的"自动"是在一组预设架构约束和固定训练流程下的自动，其优势主要体现在相对同类自动搜索算法的效率，而非绝对性能的领先。

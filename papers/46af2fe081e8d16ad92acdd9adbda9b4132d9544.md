# 图形语法的第三种实现：Wilkinson 的 GoG 如何被 Wickham 翻译成 R 语言

## 登记信息与文本核对

登记题名将本文标注为 Wickham 所著 *ggplot2: Elegant Graphics for Data Analysis*（2011），但提取文本显示，这实际上是 *Biometrics* 第 67 卷（2011 年 6 月）第 671–679 页的“书评”栏目，其中对 ggplot2 一书的评论由 Leland Wilkinson 撰写，出现在第 678–679 页 [page 8–9]。因此，本文并非 Wickham 原著本身，而是一篇由图形语法（Grammar of Graphics, GoG）的提出者撰写的书评。以下分析针对的是这篇书评的论证结构，而非 ggplot2 原书。

## 书评的核心主张

Wilkinson 的核心判断可以概括为一句话：Wickham 的 ggplot2 是 GoG 的第三种重要实现，它没有逐章照搬 Wilkinson 原书的结构，而是把 GoG 的思想重新组织成一套 R 用户容易理解的框架，从而为 R 的标准图形系统和 Lattice 包提供了一个有价值的替代方案 [page 9]。

这个判断包含两个层次。第一层是定位性的：ggplot2 属于 GoG 谱系，而非另起炉灶。第二层是评价性的：Wickham 的组织方式虽然与 Wilkinson 原书不同，但这种“不同”恰恰是优点，因为它让 GoG 的理念对 R 用户变得可及。

## 论证的起点：GoG 是什么，为什么它重要

书评的前半部分（约第 678 页）先交代 GoG 的基本框架，这是理解后续评价的前提。Wilkinson 指出，GoG 不依赖“柱状图”“饼图”“散点图”这类图表类型标签来理解统计图形，而是建立在七类正交的代数与几何规格之上 [page 8]。所谓“正交”，是指每一类包含一个或多个函数作为元素，而这七类函数的笛卡尔积中的任意组合都能产生有意义的图形。正交性带来的直接后果是高度的表达力：可以生成大量图表类型，甚至包括尚未被发现但有意义的图形。Wilkinson 进一步强调，GoG 不只是分类学，而是一个基于“表示数据统计函数的数学”的计算系统，其目标是成为生成、阅读和理解统计图形的基础。

这段铺垫的论证功能在于：它为后面评价 ggplot2 设定了一个标准——一个 GoG 实现是否成功，取决于它是否忠实于这套正交结构，以及是否能让用户有效地利用这种表达力。

## 从 GoG 到 ggplot2：谱系与定位

Wilkinson 简要梳理了 GoG 此前的几次实现：SPSS/IBM 的 nViZn 系统（包含全部七类，并有 Dan Rope 的 Graphics Production Language 解析器和 Graham Wills 设计的 XML 规格）；Chris Stolte 在斯坦福的博士论文发展出的关系数据 GoG 模型，后来演变为 Tableau 公司 [page 8]。ggplot2 被明确列为“第三种主要实现”，起源于 Wickham 在爱荷华州立大学的博士论文 [page 8–9]。

这一谱系交代的作用是双重的。一方面，它把 ggplot2 放进一个已有的技术传统中，说明它不是孤立的产品；另一方面，它暗示了一个评价维度：前两种实现各有侧重（nViZn 偏企业级平台，Tableau 偏关系数据可视化），ggplot2 的独特之处在于它是开源的、面向 R 用户的。

## 关键证据：用代码展示“表达力”

书评最有说服力的部分，是 Wilkinson 用具体的 ggplot2 代码来展示这套系统的“优雅”。他没有逐章总结原书内容，而是直接给出几个著名图表的 ggplot2 规格 [page 9]。

他先展示 `qplot` 函数的一行代码：

```
qplot(displacement, mileage, color=factor(cylinders))
```

这行代码为 cars 数据生成一个散点图，横轴是 displacement，纵轴是 mileage，颜色按气缸数（作为分类变量）区分。

然后他展示用 `ggplot` 函数实现同一图形的两行代码：

```
p <- ggplot(cars data, aes(x=displacement, y=mileage))
p + geom_point(aes(color = factor(cylinders)))
```

Wilkinson 特别指出，虽然后者用了两行而非一行，但真正的力量在于可扩展性。第一行指定了一个“框架”（frame），即由 mileage 和 displacement 的值域界定的绘图区域；第二行向框架添加点并按气缸数着色。在此基础上，只需稍作修改就能生成多种图表：

- 加入 loess 平滑：`p + geom_smooth(method = loess)`
- 按 displacement 和 weight 分面：`p + facet_grid(displacement ~ weight)`

Wilkinson 由此得出一个关键判断：GoG 的设计哲学是“让简单的事情稍微复杂一点，让复杂的事情大大简化” [page 9]。他进一步推测，ggplot2 的函数清单可能比其他 R 图形包（尤其是其他统计软件包）更小，但能生成更多不同类型的图表。

这段代码演示是整篇书评论证的核心证据。它不是抽象地称赞 ggplot2“优雅”，而是通过具体命令展示：正交的图层结构（框架 + 几何对象 + 分面）如何用少量函数覆盖大量图形类型。这正是 GoG 正交性主张在 R 语言中的体现。

## 推理中关键的一步

从“代码简洁且可扩展”到“ggplot2 是 GoG 的成功实现”，中间有一个需要补足的推理环节。Wilkinson 没有明说但实际依赖的桥接是：ggplot2 的 `ggplot` + `geom_*` + `facet_*` 结构，对应了 GoG 中七类正交规格的组合方式。框架对应坐标系和标度，几何对象对应几何规格，分面对应分面规格，颜色映射对应美学规格。因此，代码的简洁性和可扩展性不是偶然的编程技巧，而是 GoG 正交结构在 R 中的直接翻译。

这个桥接是分析者的重建，而非原文的明说。Wilkinson 作为 GoG 的提出者，可能认为这层对应不言自明，但对于不熟悉 GoG 的读者，这一步需要被点明才能理解为什么代码示例能支撑“GoG 实现”这个定位。

## 结论成立的条件与边界

Wilkinson 的正面评价有几个明确的限定条件。

第一，他的评价标准是“对 R 用户的可理解性”和“对 GoG 表达力的实现程度”，而非“对 Wilkinson 原书的忠实度”。他明确说 Wickham“显然没有坐下来逐章照搬 Wilkinson 的书”，而是“把思想组织成一个对 R 用户来说容易理解的连贯框架” [page 9]。这意味着，如果评价标准换成“是否完整实现了 GoG 的全部七类”，结论可能会不同——但 Wilkinson 没有做这个比较。

第二，他承认书有“小缺陷”，但认为不足以影响实用性 [page 9]。他更希望有更多示例和一份完整的选项与定义列表，但指出这类时效性材料现在通常放在网上（他给出了 http://had.co.nz/ggplot2/）。这说明他的推荐是“作为入门足够”，而非“作为完整参考手册足够”。

第三，他的评价带有个人视角。作为 GoG 的提出者，他对 ggplot2 的欣赏部分源于它验证了 GoG 框架的生命力。书评结尾的玩笑——“这本书比 iPad 轻一点，而且电池永远不用充电” [page 9]——虽然轻松，但也暗示他的推荐是针对纸质书的便携性，而非对内容完整性的最高背书。

## 负面结果与未讨论的限制

书评中提到的负面因素很少且轻微：少数地图的比例尺“奇怪地缩放” [page 9]；书的呈现“有些简洁”（somewhat terse）但“相当可理解” [page 9]。Wilkinson 没有讨论 ggplot2 在性能、大数据集处理、或与非 R 系统互操作方面的限制。这些不是他这篇书评的关注点，因此不能从文本中推断他对这些方面有保留意见。

同样值得注意的是，书评没有讨论 ggplot2 与 Lattice 包的具体比较——虽然提到了 Lattice 作为替代对象（Murrell, 2005; Sarkar, 2008），但没有展开两者在语法、性能或适用场景上的差异。因此，读者不能从这篇书评中获得“ggplot2 在哪些方面优于 Lattice”的具体论证。

## 总体判断

Wilkinson 的书评本质上是一个“创始人视角的验证叙事”：GoG 提出了一种理解统计图形的新模型，经过 nViZn 和 Tableau 两次实现后，Wickham 的 ggplot2 以开源、R 原生的方式实现了同样的核心理念，并且用更适合 R 用户的语言重新组织了它。论证的关键证据是具体的代码示例，展示了正交结构如何转化为简洁且可扩展的绘图命令。结论的强度是“高度推荐作为入门”，而非“完整参考”或“全面优于其他系统”。这个结论在“面向 R 用户的 GoG 入门”这个条件下成立，超出这个条件的评价需要额外的论证，而书评没有提供。

# 让候选框几乎免费：Faster R-CNN 如何用共享卷积把区域提议并入检测网络

**原文题名**：Faster R-CNN: Towards Real-Time Object Detection with Region Proposal Networks（2015，arXiv:1506.01497v3）

## 一个被暴露出来的瓶颈

在 Faster R-CNN 之前，主流检测系统的结构是"两段式"：先用一个独立模块（如 Selective Search、EdgeBoxes）在图像上生成大量候选区域，再交给检测网络分类和回归。SPPnet 和 Fast R-CNN 通过共享卷积把检测网络本身的速度大幅压缩，结果反而让原本不起眼的候选区域生成环节变成了测试时的主要耗时来源。论文开篇就把这个矛盾点明：Selective Search 在 CPU 上每张图约 2 秒，EdgeBoxes 约 0.2 秒，而 Fast R-CNN 的检测部分已经接近实时——候选框生成成了新的瓶颈 [page 1]。

作者提出的解决思路不是"把 Selective Search 搬到 GPU 上重写一遍"，而是指出这种工程加速会忽略下游检测网络、错失共享计算的机会。他们主张：既然检测网络已经在整张图上算出了卷积特征，为什么不直接在这些特征上生成候选框？这就是 Region Proposal Network（RPN）的核心动机 [page 1]。

## RPN 的机制：在共享特征图上滑窗，用锚框做回归参照

RPN 的设计可以拆成三层理解。

**第一层是结构**。RPN 是一个全卷积网络，在一个 n×n 的滑动窗口上操作共享卷积特征图，把每个窗口映射成一个低维特征（ZF 为 256 维，VGG 为 512 维），再分两路：一路做框回归（reg），一路做物体/非物体二分类（cls）。论文用 n=3，但对应的输入图像感受野很大（ZF 171 像素，VGG 228 像素）[page 3]。由于是滑窗方式，全连接层在所有空间位置上共享，实际实现就是 n×n 卷积加两个 1×1 卷积。

**第二层是锚框（anchor）**。在每个滑窗位置，RPN 同时预测 k 个候选框。每个锚框以滑窗位置为中心，配一个尺度和一个长宽比。默认用 3 种尺度（128²、256²、512² 像素面积）和 3 种长宽比（1:1、1:2、2:1），所以 k=9 [page 4]。reg 层输出 4k 个坐标，cls 层输出 2k 个分数。这个设计的关键在于：它把"多尺度"问题从图像金字塔或滤波器金字塔转移到了回归参照系上——只用单一尺度的图像和单一尺寸的滤波器，靠锚框本身覆盖多尺度 [page 4]。

**第三层是损失函数**。训练时给每个锚框打二分类标签：与某个真值框 IoU 最高的锚框、或 IoU 超过 0.7 的锚框标为正；与所有真值框 IoU 都低于 0.3 的标为负；介于两者之间的不参与训练 [page 4-5]。损失函数是分类损失加回归损失的加权和（公式 1），回归只对正锚框激活，用 smooth L1 损失。坐标参数化采用 R-CNN 的写法（公式 2），把预测框、锚框、真值框之间的偏移用中心坐标和宽高的相对量表示 [page 5]。

这里有一个容易被忽略但很重要的设计选择：与 Fast R-CNN 在任意大小 RoI 上做回归不同，RPN 的回归特征固定为 3×3，但为每个尺度和长宽比各学一组回归器，k 个回归器不共享权重。这样即使特征尺寸固定，也能预测各种大小的框 [page 5]。

## 共享特征：四步交替训练

RPN 和 Fast R-CNN 如果各自独立训练，会以不同方式修改卷积层，无法直接共享。论文讨论了三种共享方案：交替训练、近似联合训练、非近似联合训练。实际采用的是四步交替训练 [page 6]：

1. 用 ImageNet 预训练模型初始化，端到端训练 RPN；
2. 用第一步 RPN 生成的候选框训练 Fast R-CNN 检测网络；
3. 用检测网络初始化 RPN，固定共享卷积层，只微调 RPN 独有的层；
4. 固定共享卷积层，微调 Fast R-CNN 独有的层。

四步之后，两个网络共享同一组卷积层，形成统一网络。论文提到更多轮迭代的改进可以忽略不计 [page 6]。近似联合训练被报告能减少 25-50% 训练时间且结果接近，但因为它忽略了候选框坐标的梯度，是近似的 [page 6]。

## 证据链：从消融实验到跨数据集验证

论文的证据组织得很清晰，核心逻辑是：先证明 RPN 作为候选框生成器不输甚至优于 Selective Search，再证明共享特征带来额外收益，最后证明整个系统在速度和精度上都站得住。

**PASCAL VOC 2007 上的基线对比**（表 2，[page 7]）显示：SS+Fast R-CNN 的 mAP 是 58.7%，EB+Fast R-CNN 是 58.6%，而 RPN+Fast R-CNN（共享特征）用 300 个候选框就达到 59.9%。这个对比的关键在于，RPN 不仅精度略高，而且候选框数量从 2000 降到 300，直接减少了后续 region-wise 计算的开销。

**消融实验**进一步拆解了 RPN 的贡献。不共享特征时 mAP 降到 58.7%，说明第三步用检测器调过的特征去微调 RPN 确实提升了候选框质量 [page 7]。更细致的实验固定一个用 SS 训练的检测器，只换测试时的候选框：用 300 个 RPN 候选框得 56.8%，用 100 个得 55.1%，说明排名靠前的 RPN 候选框本身就很准 [page 7-8]。去掉 cls 层（不做 NMS 和排序，随机采样）时，N=1000 还有 55.8%，但 N=100 骤降到 44.6%，说明 cls 分数对高排名候选框的质量至关重要。去掉 reg 层（候选框退化为锚框）时 mAP 降到 52.1%，说明回归后的框边界才是高质量候选框的主要来源，光靠多尺度锚框不够 [page 8]。

**VGG-16 上的结果**（表 3，[page 8]）把精度推到更高：RPN+VGG 共享特征在 VOC 2007 上达 69.9%，超过 SS 基线的 66.9%；用 07+12 训练数据达 73.2%；加入 COCO 数据达 78.8%。VOC 2012 上对应为 70.4% 和 75.9%（表 4）[page 8]。

**速度**（表 5，[page 8]）是论文的另一条核心证据。VGG 模型下，SS+Fast R-CNN 总耗时 1830ms（其中 SS 占 1510ms），而 RPN+Fast R-CNN 总耗时 198ms（其中 RPN 只占 10ms），帧率从 0.5fps 提升到 5fps。ZF 模型下达 17fps。这个量级差异直接支撑了"near real-time"的主张。

**锚框设置的敏感性**（表 8，[page 9]）显示：只用 1 个锚框时 mAP 下降 3-4%；用 3 尺度或 3 长宽比都能提升；3 尺度+1 长宽比（69.8%）与 3 尺度+3 长宽比（69.9%）几乎持平，说明在这个数据集上尺度和长宽比并非完全独立的增益维度。λ 在 1 到 100 之间变化时 mAP 只波动约 1%（表 9），说明损失权重不敏感 [page 9]。

**单阶段 vs 两阶段**（表 10，[page 10]）是一个有意义的对照：用密集滑窗模拟 OverFeat 式单阶段检测，mAP 为 53.9%，比两阶段的 58.7% 低 4.8%。论文认为这是因为第二阶段的自适应池化能更准确地覆盖区域特征。这个对比为"级联式候选+检测"的设计提供了直接支持。

**MS COCO 上的验证**（表 11，[page 11]）显示 Faster R-CNN 比 Fast R-CNN 在 mAP@0.5 上高 2.8%、在 mAP@[.5,.95] 上高 2.2%，说明 RPN 对高 IoU 阈值下的定位精度提升更明显。COCO 到 VOC 的迁移实验（表 12）显示，仅用 COCO 训练不在 VOC 上微调就能达 76.1%，超过 VOC07+12 训练的 73.2%；COCO+VOC 联合训练达 78.8% [page 11]。

## 关键推理步骤与隐含假设

从证据到结论，有一个关键的推理桥接值得点明。论文的核心主张是"候选框生成几乎免费"，这个"免费"的论证依赖于一个前提：RPN 和检测网络共享卷积层后，RPN 新增的计算量相对于检测网络本身可以忽略。表 5 的数据支持这一点——VGG 下 RPN 只增加 10ms，而检测部分本身要 141ms 卷积加 47ms region-wise [page 8]。但这个"免费"是有条件的：它成立的前提是检测网络已经需要计算整张图的卷积特征。如果检测网络本身不共享这些特征，或者候选框生成需要独立的多尺度图像金字塔，那么"免费"就不成立。

另一个隐含假设是：RPN 学到的候选框质量至少不差于手工设计的候选框方法。这个假设在 VOC 和 COCO 上被验证，但论文也承认 RPN 的优势部分来自它能从更好的网络中获益——RPN+VGG 的候选框质量优于 RPN+ZF，而 SS 是预定义的、不随网络改进 [page 8]。这意味着 RPN 相对于 SS 的优势可能随网络深度增加而扩大，这一点在 ILSVRC/COCO 2015 竞赛中用 ResNet-101 的结果得到印证：仅替换骨干网络，COCO val 上的 mAP 就从 41.5%/21.2% 提升到 48.4%/27.2% [page 11]。

## 边界与限制

论文明确承认的限制包括：非近似联合训练需要可对框坐标求导的 RoI pooling 层，这超出本文范围 [page 6]；跨边界的锚框在训练时被忽略，否则不收敛，但测试时仍会生成跨边界框并裁剪到图像边界 [page 6]；Recall-to-IoU 指标与最终检测精度的关联只是松散的，更适合诊断候选框方法而非评价它 [page 9]。

从文本中可以推断但论文未明确展开的边界：RPN 的翻译不变性（translation invariance）是"up to the network's total stride"的 [page 4 脚注 5]，这意味着对于小于总步长的位移，RPN 的输出可能不完全一致。此外，论文默认使用单尺度测试（s=600），虽然提到多尺度特征提取可能提升精度但速度-精度权衡不好 [page 6]，这个选择本身就是一个工程边界。

论文没有讨论但可能影响结论的因素包括：RPN 在极端长宽比或极小物体上的表现（COCO 上增加了 64² 尺度来处理小物体 [page 10]，暗示默认设置对小物体可能不够）；四步交替训练是否在更大数据集上仍然收敛良好（论文只报告了 VOC 和 COCO 的结果）；以及共享卷积层后两个任务的梯度冲突是否在更深网络中加剧。

## 结论的力度

论文的核心结论——"通过共享卷积特征，区域提议的计算边际成本很小，且学到的 RPN 能提升候选框质量和整体检测精度"——在 PASCAL VOC 2007/2012 和 MS COCO 上都有直接实验支持，速度数据也有明确的 profiling 支撑。但需要注意，论文报告的是特定硬件（K40 GPU）和特定实现（Caffe）下的结果，帧率数字不能直接外推到其他配置。此外，"state-of-the-art"的声明是在 2015 年的竞赛背景下，后续工作（如 YOLO、SSD 等单阶段检测器）在速度-精度权衡上提供了不同的选择。论文本身也指出，RPN 和 Faster R-CNN 已被推广到 3D 检测、实例分割、图像描述等任务 [page 2]，这更多是影响力的证据而非本文论证的一部分。
